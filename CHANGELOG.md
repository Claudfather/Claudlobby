## [Unreleased]

### Fixed

- **`data-sweep` purge is now an allowlist of known-ephemeral classes — durable files never age out (#653).** The weekly purge removed *every* regular file under a bot's `data/` older than the retention window, which repeatedly destroyed static operational assets while the data they served survived: the rolling-audit tracker (`data/scripts/audit-tracker.py`) was swept for at least the third time on 2026-07-17/21, the briefing trigger scripts before it (~2026-07-04), and clog's finance snapshot scripts per the #627 evidence — each time silently breaking the machinery until someone root-caused the vanished file. The purge is now scoped to an explicit allowlist of regenerable file classes — `events/*.jsonl` (the framework event stream, the accumulator the job exists for; fleet-pulse/keepalive reaping at `OBSERVABILITY_REAP_DAYS` stays the primary ager, this is the 30d backstop), the vetted text-log names `log-rotate-fleet.sh` already rotates under `data/` (`cron.log`, `git-pull.log`, `briefing*.log`, `home-assistant.log` — deliberately *not* a bare `*.log` glob, which would also match binary LevelDB/browser-profile logs that are live state), and `*.bak` — via a single `find_stale_ephemeral` helper shared by the count and the delete so the two can never disagree. Everything else — scripts, configs, ledgers, drafts — is durable by default and never removed, wherever it sits under `data/`, so the *next* durable asset dropped into `data/` is safe without anyone remembering to exempt it (protect-by-default; a per-file allowlist was explicitly rejected in the directive). Report mode, directory preservation, `--days` override, and the composed-unit arg convention are unchanged. Supersedes plan [#628](https://github.com/Claudfather/Claudlobby/issues/628) fork F1's "zero sweep-code change" premise per the newer human directive on #653 — F1's `bin/` relocation of existing fleet-local scripts remains valid as belt-and-suspenders, but protection no longer depends on migrating every script. `tests/test_maintenance_jobs.py` now pins the contract both ways (aged ephemeral classes purge; aged `scripts/audit-tracker.py`, ledger, and notes survive). Empirically validated against the live fleet: a dummy durable script aged 40 days under `data/scripts/` survived a real `--purge` run byte-identical while its aged ephemeral twin in `events/` was the run's only purged file, and a subsequent `claudlobby generate` left it intact.

- **Slash-command dispatches now land bare so the skill actually fires (#627).** `lib/dispatch.sh` unconditionally prefixed `set +H;` on every send; for a slash command (a briefing/sprint cron sending `/skill`), the payload became `set +H; /skill`, so Claude Code never saw a leading slash and the skill was never invoked — the live briefing-cron bug. Per plan [#628](https://github.com/Claudfather/Claudlobby/issues/628) locked fork **F6**, `set +H;` is now prepended **only when the message is not a slash command**: the classifier matches a real command token (`^/[A-Za-z][A-Za-z0-9:_-]*([[:space:]]|$)` — an alpha-led word terminated by whitespace-or-end), so a genuine `/briefing morning` sends bare while file-path prose (`/home/crog/x`, `/etc/hosts`) and leading-whitespace keep the history-expansion guard; not any leading slash. A payload containing `!` also keeps the guard (so prose starting with a slash-word like `/reports is missing !!` stays guarded, and a rare genuine slash command with `!` in its args keeps it too — amended F6). POSIX `[[:space:]]` (not `\s`) for bash 3.2 / macOS `/bin/bash`. Rollback is a documented one-line revert. Mirrors the existing slash-safe send in `keepalive.sh` and `start-bot.sh`; the bare-slash-invokes precedent is `sprint-trigger.sh:35`. New `tests/test_dispatch_slash.py` (Python-wrapped bash) drives the real `dispatch.sh` and asserts the classification. FLEET-WIDE dispatch change — awaits the manager's one-manager pre-merge canary before merge.

- **Per-bot tmux socket isolation (#414).** Every bot now runs its **own** tmux server — a private `-L <socket>` equal to its `BOT_SERVICE` — instead of sharing the one per-user default server, so the death of one server can no longer drop the entire fleet's sessions at once (blast radius is now exactly one bot; the SPOF that once dropped every bot simultaneously is gone). A single SSOT helper `tmux_socket_for_bot()` resolves the socket (mirroring how `BOT_SERVICE` resolves the unit name), with `bot_tmux()`/`bot_tmux_send()` wrappers in `lib-common.sh`. **All** cross-socket sends (dispatch, report-back, fleet-pulse `notify_manager`, sprint-trigger, bot-sweep, and the shared `emit_failure_alert`) route through the one `bot_tmux_send` primitive, which prechecks the peer's socket and emits a `send_miss` event on a miss instead of the old silent `|| true`. The composer emits `TMUX_SOCKET`, `MANAGER_TMUX_SOCKET`, and a pinned fleet-wide `TMUX_TMPDIR` into `bot.conf` + both service units, and the generated systemd `ExecStop` kills on the bot's own socket. Fleet enumeration (`reconcile-fleet.sh`, `status.py`, `doctor.py`, `move_bot.py`) fans out across per-bot sockets and scans `$TMUX_TMPDIR/tmux-$(id -u)/` socket files for orphan/unbound detection. `lib/validate-bot-change.sh` is socket-aware (sessions on distinct private servers, per-socket `kill-server` teardown) and asserts the blast-radius acceptance test (kill one server → peers survive) plus `send_miss` observability end-to-end. The dispatch protocol + `dispatch`/`delegate` skills now route operators through the socket-aware `lib/dispatch.sh` (a raw `tmux send-keys -t` against the default socket no longer reaches a bot). The `.tmux-env` env-bleed workaround is kept belt-and-suspenders for v1. Forged + ironclad plan (all 5 forks locked): `documentation/plans/archive/2026-06-14-per-bot-tmux-socket-isolation.md`. **Follow-up fixes** from the paired review (#423-#426, #429): cross-fleet peer socket resolution in `tmux_socket_for_session` (a manager could not resolve a peer bot living in a sibling fleet, dropping every cross-fleet dispatch and report-back); the composer's `ExecStop` now runs `kill-server` instead of `kill-session`; `move_bot` explicitly tears down the source tmux server after a move; `doctor` resolves sockets via the same Python SSOT (`tmux_socket_for_bot`) as `status.py`; `keepalive.sh`/`pre-stop-handoff.sh` fail fast with a clear diagnostic instead of a silent `errexit` abort; and `tmux_socket_for_bot` now mirrors the bash guard's fail-fast behavior under `FLEET_NAME`, so a misconfigured bot resolves identically (and surfaces as a failure rather than a silent fallback) across both languages.

The first **dynamic** per-(bot,slot) timer family carries a stale-unit **reconciler** on both sides — `generate` prunes uncomposed `<prefix>.briefing-*` unit files, and `setup-fleet`'s new `reconcile_briefing_timers` (modeled on `migrate_legacy_keepalive` gate discipline + `spin-down-bot.sh`/`reconcile-fleet.sh` cross-platform teardown) enumerates the **live enrolled** set, dry-run-logs orphans, then disables + removes them (systemd `disable --now`; launchd `bootout gui/$UID/<label>`). These are **generate-time / on-host gates** (the real protection — `local/` is gitignored and CI runs synthetic-fixture unit tests, so cross-fleet enforcement lives at generate + `setup-fleet` + the P7 canary, not CI). `generate` and `claudlobby diff` now call `compose_fleet_timers` unconditionally (it early-returns cheaply when idle) so the new dynamic family — and the removed-stanza reconcile — are visible to both, replacing the per-caller "which timer sources are active?" guard that a `/simplify` pass found already drifted (`diff` silently skipped briefing units). ### Fixed

- **Keepalive event retention now honors the fleet retention window.** `lib/keepalive.sh` reaped `keepalive-*.jsonl` on `KEEPALIVE_REAP_DAYS`, which is never composed into `bot.conf` and so always fell back to a hardcoded 7 days — diverging from `fleet-pulse.sh` and `bot-vitals.sh`, which reap `fleet-*.jsonl` on the composed `OBSERVABILITY_REAP_DAYS` (`observability.reap_days`). A fleet that set `reap_days: N` retained its pulse/vitals events for N days but its keepalive events for only 7. `KEEPALIVE_REAP_DAYS` now falls back to `OBSERVABILITY_REAP_DAYS` (then 7), so all three event writers reap on one window; an explicit `KEEPALIVE_REAP_DAYS` still overrides. Verified: with `OBSERVABILITY_REAP_DAYS=1`, a 3-day-old keepalive JSONL is reaped and the current day's is retained.
- **`claudlobby diff` vs. `claudlobby generate` fleet-timer divergence.** `diff_fleet_timers` built a 2-attribute shadow `Paths` object and handed it to `compose_fleet_timers`, instead of a real `Paths` instance; the moment the timer path read any other `Paths` attribute, `claudlobby diff` would raise `AttributeError` while `generate` kept working. Now passes a real `Paths` plus a temp output dir, with a regression test asserting the two commands exercise an identical `Paths` surface (#442).
- **Three runtime sweeps could resurrect departed bots' directories.** `git-pull-all.sh`, `reload-fleet.sh`, and `weekly-worker-restart.sh` acted on every directory under `runtime/bots/` without consulting `fleet.yaml`, so a cron/timer tick could re-create and poke orphaned directories for bots no longer declared in the fleet (surfacing as false "orphan" reports elsewhere in supervision). All three now consult the shared `bot_in_fleet` predicate before acting (#419, #448).
- **Dead code removed and Telegram-handle validation unified.** Dropped four unreferenced symbols (`McpEntry.is_multi`, `McpEntry.server_names`, `ValidationReport.merged_for_strict`, the legacy `loader.load_library_items`) and collapsed two divergent telegram-handle regexes into one `_TELEGRAM_HANDLE_RE` shared by `compose_bot_conf` and `compose_bot`, so a handle can no longer be accepted by one composition path and silently dropped by the other. Also fixes a latent `NameError` under `typing.get_type_hints` in `composer.py` (#430, #431).
- Fixed a `test_uptime` aggregate test that hardcoded a 2026-05-17 timestamp and had been silently failing (then deselected from CI) since the following day; it now stamps a relative timestamp so it stays in-window regardless of the calendar date, and CI re-enables the test (#444, #446).
- **MCP-trust allowlist no longer wiped by `generate`.** `settings.local.json` now emits a per-server `enabledMcpjsonServers` allowlist derived from the bot's composed MCP servers, re-derived on every `generate` instead of being lost, so a headless `claude --permission-mode auto` boot no longer stalls on an MCP-approval prompt after a daily `reload-fleet`. Fails closed: servers outside the fleet-configured set still prompt rather than being blanket-trusted (#453 Phase 4, #465).
- **Keepalive no longer misreads a busy bot as idle.** Liveness detection depended on a braille spinner plus a hardcoded verb list, which missed bots on newer TUI states (whimsical verbs, reduced-motion) and risked injecting reload keystrokes into a bot that was actually mid-task. Liveness now keys off the same `.last-tool-call` marker fleet-pulse already trusts, plus the "esc to interrupt" active-turn affordance, erring toward treating a bot as active (#472).
- **`overdue_dispatch` no longer re-fires forever for an abandoned dispatch.** A dispatch that never received a terminal report re-emitted an `overdue_dispatch` event on every fleet-pulse cycle indefinitely (one case produced 232 events from a single ~19-hour-old dispatch). The matcher now expires dispatches past a max age (default 24h, `DISPATCH_OVERDUE_MAX_AGE_S`, disable with `<=0`) (#460, #466).
- **`claudlobby generate` failing under systemd/launchd supervision.** `Paths.detect()` only walked up from the process's working directory, but the daily `reload-fleet` timer unit exports `CLAUDLOBBY_ROOT` while running from the supervisor's default cwd -- so `generate` died with `FileNotFoundError` before composing anything. `detect()` now resolves in explicit precedence order (hint > `CLAUDLOBBY_ROOT` env > cwd walk-up), and generated systemd/launchd timer units pin `WorkingDirectory=<root>` so no timer job depends on its spawn cwd (#479).

### Security

- Restrict .env file permissions to 0o600 (owner read/write only) in scaffold_env_files and env-migrate. Previously these files were created with default umask (typically 0o644), making fleet secrets world-readable on shared hosts.
