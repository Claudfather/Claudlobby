# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Removed

- **`claudron/` subpackage** — extracted to its own repo ([Claudfather/Claudron](https://github.com/Claudfather/Claudron)). Removed source, CLI entry point, and all claudron-specific tests from this repo. `test_paths_integration.py` (which tests claudlobby's vault-aware path resolution, not claudron internals) moved to `tests/`.

### Added

- **`fleet-dispatch-capability` protocol** (`library/protocols/fleet-dispatch-capability.md`). Pairs with the now-clauDNA-resident, subagent-only `/ironclad` skill: the skill's dispatch preamble checks for this protocol in the composed `CLAUDE.md` and, when present, follows it **instead of** subagent dispatch — substituting `/ironclad`'s lens execution with fleet dispatch (idle-worker selection from `fleet-state.json`, tracked dispatch via `lib/dispatch-task.sh`, `[BOTREPORT]` collection with `OBSERVABILITY_DISPATCH_DEADLINE` timeout, retry on a different worker) while leaving classification, aggregation, comment format, and convergence to the skill. Persistent scratch under `state/ironclad-runs/` preserves fleet multi-cycle and prior-comment minimization. Wired onto the `lead` manager in `fleet.yaml.example`. Phase 3c of the /ironclad migration (skill landed in clauDNA via Claudfather/clauDNA#146).
- **Empirical bot-behavior validation loop (Deliver → Add config → Recompose → Observe).** Institutionalizes the discipline that *unit tests prove composition, only running proves behavior*. New `lib/validate-bot-change.sh` stands up a throwaway bot + tmux sessions in a temp root and asserts the observability/trust-loop behaviors (`activity_stuck`, `overdue_dispatch`, manager `[FLEET-PULSE]` push) actually fire end-to-end — no Claude auth or real fleet needed; gated in CI via `tests/test_validate_harness.py` (skips without tmux). Mandatory contributor checklist added to `CLAUDE.md`; `documentation/validating-bot-changes.md` documents the loop; the review lesson `library/lessons/review/empirical-verification.md` gates bot-behavior PRs on a cited Observe step. The harness immediately caught a latent `fleet-pulse.sh` bug — a `bot.conf` missing `BOT_SERVICE` aborted the whole sweep under `set -euo pipefail` (now guarded with `|| true`).
- **Manager-side dispatch watchdog (`overdue_dispatch`).** `lib/dispatch-task.sh` records a dispatched task to `state/dispatch-log.jsonl` (`{ts,manager,bot,task,dispatched_at,expected_by}`) then sends via `dispatch.sh`. `fleet-pulse.sh` cross-references the dispatch ledger against the `report-back.jsonl` ledger (via the testable `lib/dispatch-overdue.py` matcher): a task whose deadline passed with no terminal report (completed/failed/blocked) is flagged `overdue_dispatch` and pushed to the manager's session, debounced and auto-closed when a matching report lands. Deadline is config-driven: `observability.dispatch_deadline` (default 1800s) → `OBSERVABILITY_DISPATCH_DEADLINE` in `bot.conf`, override per-dispatch with `--deadline-min`. Decision-table row in `fleet-observability.md` + manager contract in `dispatch.md`. Automates the manual "poke an overdue worker" so it doesn't depend on the manager remembering to poll. Resolves [#318](https://github.com/Claudfather/Claudlobby/issues/318).
- **Activity-based stuck detection (`activity_stuck`).** `fleet-pulse.sh` now flags a bot whose session is alive and not idle but has made **no tool call** beyond a threshold — the animated-but-hung case that pane-hash `pane_stuck` can't see (a live spinner keeps the pane changing). The signal is the `.last-tool-call` marker that `bot-vitals.sh` touches on every tool call; the gap is checked against `OBSERVABILITY_ACTIVITY_STUCK_THRESHOLD` (new `observability.activity_stuck_threshold`, default 1800s, composed into `bot.conf`). On `activity_stuck`/`session_missing`/`service_down`, fleet-pulse also pushes a debounced `[FLEET-PULSE]` note into the manager's tmux session (the channel `report-back.sh` uses) so silent stalls get noticed in minutes, not hours. `fleet-pulse.sh` is now enrolled by `install-cron.sh` (cadence from `OBSERVABILITY_PULSE_INTERVAL`); both writers now honor `OBSERVABILITY_REAP_DAYS`. Decision-table + worker "you are monitored" guidance added to `library/protocols/fleet-observability.md` and `worker-lifecycle.md`. New shared `pane_is_idle` helper in `lib-common.sh`. Resolves [#311](https://github.com/Claudfather/Claudlobby/issues/311).
- **`claudlobby move-bot` command** — migrates a bot between fleets. Auto-detects source fleet, copies `.env` secrets and `memory/` files (atomic temp-dir-then-rename), stops and removes the old service (systemd/launchd), regenerates the target bot, updates Telegram `access.json` group chat, and re-enrolls via `spin-up-bot.sh`. Dry-run by default, `--apply` to execute, `--force` to override active tmux session check. `--cleanup-source` removes the old bot dir. Pre-flight checks: uncommitted WIP, missing target stanzas, active tmux sessions, and target fleet validation — all run before any mutation. Returns non-zero on enrollment failure or access.json update failure. 14 tests. Resolves [#298](https://github.com/Claudfather/Claudlobby/issues/298).
- **claudron external dependency for vault-aware path resolution.** `claudlobby/paths.py` now uses `claudron.vault.detect()` for proper vault fleet discovery when claudron is installed (`pip install claudlobby[vault]`). Falls back to built-in `.claudron` bridge file parsing when claudron is not available. Resolves [#299](https://github.com/Claudfather/Claudlobby/issues/299).
- **Phase 4 Part A — autonomous-runner schema layer.** New `autonomous_runner` block on `BotConfig`, parsed from `fleet.yaml` by `_coerce_bot`, validated in `validate()`, rendered into the bot's `CLAUDE.md` by `compose_claude_md`. Adds three dataclasses (`AutonomousRunnerConfig`, `AutonomousRunnerPicker`, `AutonomousRunnerBypass`) and 23 new tests across `test_config.py`, `test_validator.py`, `test_composer.py`. The wrapper-skill body, risk-classifier prompt, fleet.yaml example, and Autonomous Worker archetype docs live in Part B (issue #279). See [Claudfather/Claudlobby#278](https://github.com/Claudfather/Claudlobby/issues/278).
- **Phase 4 Part B — autonomous-runner skill body.** New `library/skills/autonomous-runner/` with `SKILL.md` (the 10-step wrapper procedure: idle check, quota, pick, classify, pre-hooks, invoke, parse, post-hooks, on-outcome, state update), `risk-classifier-prompt.md` (the `structural_vs_mechanical` subagent prompt template), and `archetype.md` (the "Autonomous Worker" composition recipe). `fleet.yaml.example` gains a commented `autonomous_runner` block and a complete `dbt-auto-bot` example bot stanza. clauDNA skills are invoked through the Skill tool as plugin-namespaced commands (e.g., `/claudna:implement-plan --auto`); no filesystem-path references. 12 markdown sanity tests in `test_autonomous_runner_assets.py`. End-to-end validation deployment is deferred to Phase 4 Part C. See [Claudfather/Claudlobby#279](https://github.com/Claudfather/Claudlobby/issues/279).

### Security

- Restrict .env file permissions to 0o600 (owner read/write only) in scaffold_env_files and env-migrate. Previously these files were created with default umask (typically 0o644), making fleet secrets world-readable on shared hosts.
