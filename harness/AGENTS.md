# harness/ — validation and measurement instruments

Instruments that prove or measure fleet behavior: end-to-end harnesses, canaries (`rehearse-*`),
real-boot samplers, A/B evaluations and their analysis. None runs in production; the fleet runs on
the public CLI and `claudlobby/_runtime_scripts/`. The root `CLAUDE.md` points here; this file is
the index and the rules.

## Index

- `validate-bot-change.sh` — end-to-end harness for bot behavior changes (throwaway bot + tmux); writes and starts user units under `$HOME` and leaves empty ones: give it a scratch HOME, as CI does
- `coldstart-harness.sh` — prepare and reap for the cold-start onboarding simulation
- `compose.py` — runs the compositor for these instruments without selecting or activating a release
- `freshbox-boot-gate.sh` — boots a bot on a fresh config dir; checks composed permissions hold
- `naked-bot-observe.py` — records what a bot gets from a fleet that declares nothing
- `boot-strand-sampler.sh` — real-boot sampler for startup prompts left unsubmitted
- `boot-strand-summary.py` — statistics for `boot-strand-sampler.sh`
- `send-size-probe.sh` — how much of a large pane send reaches the reader
- `rehearse-env-cascade.sh` — canary for the `.env` tier cascade on a throwaway bot
- `rehearse-staged-claude-update.sh` — canary for the staged Claude Code update
- `rehearse-plane-durability.sh` — canary that gates changes to the plane daemon's checkpointing
- `plane-durability-driver.py` — that canary's client and loss witness
- `plane-canary-sampler.py` — that canary's passive daemon sampler
- `plane-canary-compare.py` — that canary's comparator (self-tested)
- `plane-parity.py` — reconcile an archived JSONL ledger against the plane
- `rehearse-debounce-recipient.sh` — proves a debounced page survives a manager restart
- `rehearse-held-push.sh` — proves no page is typed into a held box, and a box that takes no input costs one wait per floor
- `rehearse-briefing-timer.sh` — rehearses the briefing-timer chain on a throwaway fleet
- `rehearse-permissions-ladder.sh` — single-factor permissions ladder on a disposable bot
- `rehearse-vault-sync.sh` — proves `vault-sync.sh`'s outcomes against a real plane
- `vault-git-base-rate.py` — how often state-changing git reaches the vault guard directly
- `runtime-neutral-canary.py` — P0 canaries for #2145 (Claude C6a/C10/C11, Codex C1–C3): raw OTLP receiver, hook logger, tmux env probe (shapes and ids, never content)
- `ab-comms-eval.sh` — A/B harness for the token-efficiency comms eval
- `ab-comms-verdict.py` — pass bar and verdict for `ab-comms-eval.sh`
- `ab-coverage-verdict.py` — coverage-honesty A/B analysis
- `ab-channel-brevity-verdict.py` — channel-brevity A/B analysis
- `ab-recoverability-scorer.py` — scores whether compressed-out detail is recoverable in full
- `ab-recoverability-judge.py` — semantic judge for that scorer

## Script reference

What each script does and how, its flags, outputs and measurements, and its history are in
[`documentation/harness-script-reference.md`](../documentation/harness-script-reference.md), row by
row in this table's order.

A script indexed above without a row documents itself in its header.

| Script | Purpose |
|--------|---------|
| `harness/rehearse-env-cascade.sh` | Asserts resolution from each of the four tiers independently, most-specific-wins, an operator's empty assignment winning, the scaffolder's `provided_upstream` guard neutralising a pristine stub so the upstream value survives, survival of a full down/up cycle — and the load-bearing one, that **the TOOLING agrees with the RUNTIME**. That last assertion must exercise the doors PRODUCTION uses, not the doors a PR adds: the first version compared only `Paths.env_resolved`, which at the time had no other callers, so the canary was the sole thing exercising it while `credentials.py` — the door that actually runs — went untouched and its defect passed. A harness that reaches for the new API certifies a dead path. Safety is structural rather than careful: everything happens inside a disposable `git archive` export, `--purge` is refused by path check for anything outside it, `HOME` is redirected so the operator's real `~/.env` is never read, and the harness ASSERTS that isolation held (a canary that silently fell back to the real host tier would pass by coincidence). Boundary: boots with a STUBBED `claude` (the `validate-bot-change.sh` convention), so it proves env resolution and lifecycle, not Claude Code consuming the vars — `boot-strand-sampler.sh` is the instrument for real boots. |
| `harness/ab-comms-eval.sh` | Task content + quality rubric are F2 stubs; `--dry-run` is CI-safe (synthetic transcripts, zero model calls); real mode (`AB_EVAL_REAL=1`) is refused pending F2 + P1. |
| `harness/ab-comms-verdict.py` | #729 stage-C pass-bar / verdict for `ab-comms-eval.sh` — pairs per-rep deltas by task, runs a seeded bootstrap CI on the median relative reduction per axis, and applies the cost-weighted-co-primary, per-task, INCONCLUSIVE-never-PASS bar (no F2-ratified threshold → INCONCLUSIVE by construction). |
| `harness/ab-recoverability-scorer.py` | Two tiers, separated so the cheap half runs without spend: STRUCTURAL (zero model calls, no tunables) contributes one sound one-way refutation — a follow-up no longer than the message it expands cannot have returned the detail, so it refutes without a judge and never confirms; SEMANTIC (`in_full`, `unre_summarised`) needs a judge and is consumed from `--judgements`, never called here, so the spend seam stays in the harness behind its existing keys. An unjudged pair is UNSCORED (`None`), never a failure — a missing judge must not manufacture a regression. Emits a comparable per-(task,variant) recovery rate plus the control-vs-treatment delta and **no verdict**: A1's bar is ratified at 25% CI-low, A2's is must-not-degrade and unratified, so inventing one here would pre-empt a ratification that has not happened. |
| `harness/ab-recoverability-judge.py` | #881 A2 semantic judge — fills the slot `ab-recoverability-scorer.py` leaves open, and does not redefine its contract: judge emits judgements, scorer consumes them, **neither decides anything**. Fails **closed**: an unreadable verdict is omitted, never guessed, so a flaky judge degrades coverage (surfaced as UNSCORED) instead of manufacturing a result. Real calls are two-key (`--real` + `AB_JUDGE_REAL=1`) and deliberately NOT the matrix's `AB_EVAL_REAL`, so a judge run can never ride in on an eval gate; `--dry-run` drives the real prompt + parse path at zero cost. `--calibrate` scores it against hand labels and reports agreement **per boolean, never pooled** — `in_full` is the easy axis, `unre_summarised` is the one the anti-lossy guard rests on, and a blended figure hides a coin flip on the second. |
| `harness/ab-coverage-verdict.py` | #866 coverage-honesty A/B analysis — pre-registered endpoints over the experiment rows: paired relative deltas (length primary, frozen-regex verification density secondary), seeded bootstrap CI imported from `ab-comms-verdict.py`, manipulation-check disclosure rates, INCONCLUSIVE-first decision rule; zero-baseline pairs and invalid rows disclosed, never silently dropped |
| `harness/validate-bot-change.sh` | **Every pane a send must land in is the input-box stand-in** (`VAL_BOX`, `tests/fixtures/input-box-stub.py`; `--chrome` where the box's geometry is under test): since #1236 a send presses Enter only once the box shows the payload, so a `cat` or `sleep` pane, which draws no box, is correctly never submitted to. Each stand-in the harness starts goes through lib-common's `harness_box_up` (`val_box_up`), which returns once its box is drawn: the stand-in enters raw mode before it draws, and keys typed before that are lost (#2139). **It reads the plane only through the stdlib doors** (`plane-readers.connect` for SQL, `plane-lookup.py` for events), never the `sqlite3` CLI, which a host need not have: the fleet's primary Pi has none, and 22 checks failed there with no reason given while CI passed (#1777). **A read that cannot run REFUSES every check after it in its scenario**: every plane read goes through `val_read`, whose reason lands in a refusal ledger (`HARNESS_REFUSALS`, through lib-common's `harness_refuse`), and each later `harness_check` FAILS naming it, whatever its verdict. A check that did not need the read is refused too, the safe direction. `val_scenario` prints a scenario's header and is its boundary (`harness_scenario`): a refusal no check has reported yet carries into the next scenario, and one never reported fails the run (`harness_finish`), so no read may be consumed past the next `val_scenario`. That rule, the `val_read` rule, and a guard on every grep in an assignment (an unguarded one ends the run under `set -e` when it matches nothing) are ratcheted in `tests/test_validate_harness_reads.py`; a run that does abort prints `=== ABORTED … ===` where the summary would be. The line keeps its `FAIL` prefix, so every reader counting failures counts it; the summary names how many were refused on a line of its own, above the unchanged `=== N passed, M failed ===`. The `#1485` stale-db stamp is the one write, done through stdlib `sqlite3` with `mode=rw` so it never creates a db, and a stamp that cannot land refuses its precondition check. |
| `harness/coldstart-harness.sh` | Reap only ever removes units/sockets/processes *absent from the pre-run snapshot*, so a production fleet on the same host is invisible to it; its state lives outside the exported tree because the tree is what gets deleted. Driven by the `simulate-cold-start` skill — the cold arm itself must be a fresh interactive session, since a subagent inherits the parent's skill registry and can never invoke `/setup` |
| `harness/freshbox-boot-gate.sh` | Gated job (deps absent → skip); wrapped by `tests/test_freshbox_boot_harness.py` (opt-in `FRESHBOX_REALBOOT=1`) |
| `harness/boot-strand-sampler.sh` | Clean = the marker in the session transcript, as a typed user-role record or a `queued_command` attachment (how a prompt typed mid-turn arrives; tool results never count): pane-independent ground truth; strand = deadline + `pane_holds_unsubmitted` (last-glyph anchored, #843); anything else = `other`, never counted clean. Wrapped by `tests/test_boot_strand_sampler.py` (real smoke opt-in `BOOT_SAMPLER_REALBOOT=1`) F18 closure R2b-2: the probe's `send_retry` count reads the plane; a count it cannot read is UNKNOWN (nothing printed, rc 1 with the reason on stderr; `null` in the row, `[send_retry UNKNOWN: …]` on the boot line, kept out of both strata by the summarizer) — never a `0`. `--no-channels` composes the probe with `channels: []` and refuses before boot 1 if its `bot.conf` still carries `--channels`: the default probe starts the Telegram channel with no token, and a channel a bot cannot authenticate poisons the host-global MCP auth cache every bot reads. |
| `harness/send-size-probe.sh` | Boots a real `claude` in a throwaway tmux socket, a scratch cwd and a throwaway `CLAUDE_CONFIG_DIR` seeded with onboarding/theme/trust and **no credentials**, against `ANTHROPIC_BASE_URL=http://127.0.0.1:9` — it cannot spend and touches no fleet; the trust key is seeded against the RESOLVED cwd, since macOS `$TMPDIR` is a symlink and the unresolved form leaves the workspace untrusted, whose wizard satisfies the input-glyph probe and whose default option QUITS. A **positive control** (100 bytes, must be recorded and whole) REFUSES the run at rc 3 rather than publishing a fleet-wide loss that is really a harness defect. Each payload is exactly N bytes with a marker at head AND tail, so a record is findable however it was cut; verdicts are whole / head-lost / tail-lost / absent / **other**, and `other` is never rounded into the nearest bucket — that is what surfaced a recipient-side chunk drop. Gated on `SEND_PROBE_REAL=1`; reaps its server, its socket file and its scratch tree on every exit path, refusing any path that is not its own. |
| `harness/rehearse-staged-claude-update.sh` | Isolation is structural and ASSERTED: the job runs under `env -i` with the base's HOME, root and plane socket, `CLAUDE_UPDATE_FLEET_PATH` is an empty dir so it cannot even measure the host's claude, and the live binary and live fleet link are fingerprinted before and after (a change exits 3). |
| `harness/rehearse-plane-durability.sh` | The #1693 canary — the INSTRUMENT that gates a change to the daemon's checkpoint behaviour, never the change itself. **The witness is the CLIENT's own log** (`plane-durability-driver.py`), written the instant a reply arrives — never a query asking the plane whether the plane lost something, which is worthless if the plane is what is lossy. **The comparator proves it FIRES on every run** (`plane-canary-compare.py`): the control cannot, because under per-batch-close `lost == 0` is guaranteed before the harness starts, so a comparator that always answers "not lost" is byte-identical there — it validates no false POSITIVES and says nothing about false negatives. A witness holding a known acked id is fed against a ledger set MINUS that id, and it must name it AND name only it; a detector that does not fire FAILS the harness. Safety is structural and ASSERTED: db and socket both derive from `root`, so one disposable root isolates both, `_assert_disposable` refuses on the PATH (against this checkout's real db and any live plane under `$HOME`), the running daemon's `/proc` cmdline is checked to name the canary root before anything is SIGKILLed, and the real plane's mtime is compared before and after. **BOUND: SIGKILL tests DAEMON death** — the WAL is a file and survives the process whether or not anything was fsync'd, so a zero here is not evidence about host death. `rehearse-*` family sibling; sampler is `plane-canary-sampler.py`, which reports its ACHIEVED rate and refuses below half the requested one. The harness enters the checkout under test and refuses when its interpreter imports another one, because `python -m claudlobby` resolves the package from the working directory, so an arm is decided by where the harness stands |
| `harness/rehearse-debounce-recipient.sh` | Prove on real tmux that a debounced FLEET-PULSE alert survives a manager restart (#831) — drives the real `fleet-pulse.sh` against a throwaway bot with an unresolved condition, restarts the manager session, and asserts the push lands in the new one; isolated sockets + a fake escalation chat so it can never page the real operator. |
| `harness/rehearse-briefing-timer.sh` | F18 closure R2b-2: the fired-trigger assertion reads the `briefing_dispatched` event from the plane (`--type briefing_dispatched`; the door's refusal reason is logged, never swallowed). |
| `harness/rehearse-permissions-ladder.sh` | Four properties are wired as CHECKS rather than stated as instructions, which is the whole difference from the predecessor: the positive control `C1` runs FIRST and `B0 == C1` stops the run (a harness that cannot tell the arms apart makes nothing downstream count); HOME redirection is ASSERTED both ways — strace proves the operator's real `~/.claude/settings.json` is never opened, an mtime check proves it was never written — because a harness that silently fell back to the real global would PASS BY COINCIDENCE, which is the exact failure that produced the thread; error strings are captured VERBATIM with the tool name, since `Permission to use Bash with command …` and `File is in a directory that is denied …` are different code paths and a paraphrase destroys the discriminator (it did); and preconditions are recorded from a PRIOR step before every cell. The canary declares `channels: []` and `mcp: []`, and the composed `bot.conf` is GREPPED for `--channels` before any boot rather than the declaration being trusted — omitting the keys is NOT opting out, the composer defaults a bot to `--channels`, and a canary that starts a channel it cannot authenticate poisons a HOST-GLOBAL MCP auth cache every bot reads (five bots across three fleets went Telegram-dark for four restarts on 2026-08-25). Safety is structural rather than careful — disposable `git archive` export, redirected HOME, read-only probes, no production bot and no credential target — and the credential scrub runs BEFORE the `LADDER_KEEP` early-return, because a keep-mode exit that skipped it left a live copy of the operator's `~/.claude/.credentials.json` in `/tmp` during development. Arm `C` is the in-workspace ladder; arm `D` is the out-of-tree one, and its positive control is a DIFFERENT cell — arm D run in-workspace would put its control on the C1 configuration, which allows, so the control passes, every cell reports, and the arm silently measures the question it was built to escape. **BOUNDARY: cells are headless `claude -p` runs, not interactive tmux boots** — the permission decision is a CLI-layer one, but that is a claim about the layer, not a measurement of a tmux session. Exit 0 ladder ran / 1 harness integrity failed / 2 precondition or dep missing; 0 means the ladder COMPLETED, not that every `harness_check` passed, which matters if it is ever wired into an automated gate. |
| `harness/plane-parity.py` | Join contract doors must honor: `source_ref = "<ledger-name>:<legacy-id>"` on every emitted envelope — parity then needs no per-door schema. Unreachable ≠ empty: absent/unreadable ledger or db (or a db with no plane schema) REFUSES at rc 3, while an existing empty ledger is a door that has not fired yet (rc 0, says so); malformed and id-less rows counted + disclosed, never dropped; rc 1 = parity broken |
| `harness/naked-bot-observe.py` | `freshbox` is the plan's named primary instrument and is run and recorded, but it is a FLOOR, not the gate: measured, it reports `OK — Self-contained` on a bot carrying six undeclared protocol sections, because it audits grants and never opens `CLAUDE.md` — blind to the INSTRUCT tier by construction, which is the tier Phase 3 exists for. **`_assert_compositor` refuses to run** unless the subprocess resolved the exported package — an editable install is normally importable, and a run against a stale one comes back green having tested nothing, a failure mode that is a PASS. Every negative carries a positive control (`guardrails` for the opt-out; a real declared skill for the wiring), because a probe that has not found something known is not evidence. |
