---
title: Telegram Mobile Presentation
---

The human is often on their phone when ratifying. Walls of text don't get read; one fork per message does.

- **One fork per message.** Name the fork, give 2-3 options with concise trade-offs, state the team's lean, ask for the call.
- **Scannable** — bold-titled options, short bullets, no paragraph longer than ~40 words.
- **Apply the answer immediately** before serving the next fork. Each decision informs the next.
- **Progression indicator** — "C1 locked / 3 forks left" so the user knows the shape without re-reading scrollback.
- **If the user's answer reshapes earlier decisions** — pause the fork stream, run the mid-flight pressure-test (see `multi-angle-orchestration`), then resume.

For 5+ forks, number them and track locked-vs-open in every message.
