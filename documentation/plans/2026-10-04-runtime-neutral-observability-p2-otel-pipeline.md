## Summary

Three PR legs, in this order. **PR P2-b (S, first, independent)** stops `bot-vitals.sh` emitting `tool_call` (~84 % of
system-event volume, `claudlobby/plane/retention.py:84-87`), leaves the `session_event` removal to the in-flight
#2140 branch (whichever of the two lands second rebases), and fixes #874's `${BOT_DIR:-${PWD}}` fallback in the same
file; it needs nothing from the intake or P0, and its evidence is two columns it produces itself — the
before-leg's day of `tool_call` rows and the transcripts' `tool_use` counts for the same sessions — recorded in the PR
body beside a 48-hour canary-root check, not a week-long canary. **PR P2-a1 (M, after Half A and C6a)** buys the raw
layer per F4(c) as amended (A-F4) and F3(b): a `telemetry` mapping in `fleet.yaml` composed into an armed Claude bot's
`bot.conf` — six export lines, eight with `content: full`, among them `OTEL_EXPORTER_OTLP_PROTOCOL=http/json` and
`OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4319`; one dormant `unit: service` host job, `plane-otel`, a stdlib
OTLP/HTTP-JSON receiver that answers `200` once the body is on disk and keeps the raw, rotated
`state/otel/{logs,metrics}.jsonl` (≈ 1.92 GB bound, a 0700 directory, `UMask=0077`, content-bearing attributes dropped
for a non-`full` bot, retention by `--retention-days` on its script line); the `otel sink` rung in `plane doctor`; the
A-F4b warning and `host doctor` rung for a bot with telemetry enabled on a host whose intake is not enrolled; the switch,
doc and table rows; then the one-bot, one-host, one-week canary (C6b) on an independent canary root. **PR P2-a2 (S–M, after that week)** lands the plane leg with its first
reader (A-F3): the intake's vendor→house mapping dict (the F5 artefact, A-F5 — Claude's `claude_code.*` names), the
allowlist → five `session.*` samples and two events (`api_error`, `tool_failure_streak`) through
`fleet_event_request` → `daemon.send_batch(timeout=5.0)`, the `PY_WRITERS` entry, derive-not-mint for `session`
subjects, the `usage_read`/`brief_read` repoint to `session.tokens` + `session.api_requests`, the design v2 §9b
decision, a harness scenario and its own gate. Deliberately left to others: Codex composition (`[otel]`, F11) and the
Codex table of the mapping dict (the companion, after the P0 Codex batch, C1–C5), traces (none composed, §2.3), any
reader UI over `session.*` samples, and a `plane samples` grant to `fleet-digest` (no P2 PR grants it).

class TelemetryConfig:
    enabled: bool = False          # STRICT bool (#2145 F4): the arming knob
    content: str = "metadata"      # metadata | full — KNOWN_TELEMETRY_CONTENT

# _parse_strict_mapping / _merge_fieldwise — plan 6 Task 1 Steps 4–6 (tests, bodies + registry, provenance); specification kept here, carried only if P2-a1 lands first
def _parse_strict_mapping(raw: Any, where: str, fields: dict[str, Callable[[str, Any], Any]]) -> dict:
    """One tier's strict mapping → the fields it SETS (absent keys stay absent so the merge inherits
    them; `null` unsets, so `content: null` inherits). Unknown keys are refused by name."""
    if raw is None:
        return {}
    raw = _shaped(f"'{where}'", raw, dict, "{" + next(iter(fields)) + ": …}")
    unknown = sorted(str(k) for k in raw if k not in fields)
    if unknown:
        raise ValueError(f"'{where}': unknown key(s) {', '.join(unknown)} — accepted: {', '.join(fields)}")
    return {k: parse(f"{where}.{k}", raw[k]) for k, parse in fields.items() if raw.get(k) is not None}

def _merge_fieldwise(cls, defaults_raw: Any, bot_raw: Any, name: str, key: str, fields: dict):
    """Field-wise: bot over defaults over built-in (observability's precedence, isolation's strictness)."""
    return cls(**{**_parse_strict_mapping(defaults_raw, f"defaults.{key}", fields),
                  **_parse_strict_mapping(bot_raw, f"bots.{name}.{key}", fields)})

_TELEMETRY_FIELDS = {
    "enabled": lambda where, v: _strict_bool(f"'{where}'", v),
    "content": lambda where, v: _parse_enum(where, v, KNOWN_TELEMETRY_CONTENT),
}

  Windows are keyed on the **data's** timestamps, so an exporter's retry after an intake outage lands in its original window and re-emits the same derived `event_id` → `duplicate`, never a double count. **A window flushes exactly once:** a record that arrives for a window already flushed is counted `late` and dropped (the raw file keeps it), so no batch ever mixes seen and unseen ids and nothing is retried (`require_commit` is never used); a `send_batch` `OSError`/`ValueError` → `dropped`, the window discarded; a `contract_violation` reply → `refused`, logged once per message text (a caller bug), and the flusher moves to the next window — a deterministic refusal never blocks it. A crash loses at most the open windows; a clean stop flushes them. **Events are per 60 s window, with no cross-window state:** `api_error` is one event per session per window carrying `count` and `exhausted`; `tool_failure_streak` is ≥ 3 consecutive failures for one tool **inside one window** — a streak straddling two windows is two shorter runs, the bound Step 2's straddle cell pins (2 + 2 → no event, 3 + 1 → one). These two definitions are the ones of record; no bounded cross-window counter is built. `fleet` is the bot's fleet alias or `"_host"` (a session with no `claudlobby.bot`); **`subject = session_alias(id, runtime)`** — imported, never re-spelt — so the derived uid is the doors' by construction; `subject_parent = "bot:<fleet>/<bot>"` when known. ## Stated limitations

- **The intake is the bots' only endpoint** (A-F4): while it is down, an export rides only the exporter's own buffer and retry, and an outage longer than that loses the interval — the raw files show the gap. **Measured (C6a, 2026-10-05):** a 35 s outage lost every log event emitted in it (none arrived later); metrics survived because the 60 s export fell after recovery; a session that ended inside the outage delivered nothing. So an intake restart costs its window's events (`session.tool_calls`, `session.api_requests`, `api_error`, `tool_failure_streak` undercount) while `session.tokens` (a metric) holds across a restart shorter than the interval. A protocol mismatch is a refusal the exporter sees (415/400) and a count in the stats line, never a silent `200`; a retried export can repeat a raw line (the plane's derived `event_id` absorbs the repeat, the raw file keeps it).
- **The content gate keys on `claudlobby.content`.** For a resource not composed `content: full` (or carrying no `claudlobby.content`), the raw writer drops the `CONTENT_KEYS` attributes before the write; content under any other key would pass, so the canary checks for a `prompt` attribute (Verification Checklist) and the files stay 0600 under a 0700 directory.
- **Codex composition is the companion's (F11), and so is the Codex table of the mapping dict.** This plan maps Claude's `claude_code.*` names only and cuts no Codex fixture; the Codex table and its fixtures follow the P0 Codex batch (C1–C5). A Codex session carries no bot (`fleet = "_host"`, no `subject_parent`) until the companion stamps `[otel] environment = "bot:<fleet>/<bot>"` (C5), and `metrics_exporter = "none"` + `[analytics] enabled = false` are the companion's lines (§11).
- **No traces.** Nothing is composed to export them (beta on Claude Code, undocumented on Codex; §2.3), the intake answers 404 on `/v1/traces`, and the envelope's `trace_id`/`span_id` stay unwritten.
- **The intake keeps no cross-window state.** A restart loses at most the open windows (a clean stop flushes them); a session's total is `SUM(value)` with that bound stated in every `METRIC_NAMES` description; a `tool_failure_streak` straddling two windows is two shorter runs and may not be reported; a late record for a flushed window is counted, not recorded.
- **Vendor names live in one dict** (A-F5): `VENDOR_TO_HOUSE` is the F5 artefact. A vendor rename is absorbed there and in fixtures re-cut from the raw files; `METRIC_NAMES`/`SYSTEM_EVENT_SEVERITY` are the reader surface that does not move, and no `gen_ai.*` name is written anywhere.
- **The first reader's sample path** covers a window only when the bot exported before the window began, and an intake outage inside the window undercounts it (the stats line and the raw files show the gap); `main`/`sidechain` stay transcript facts, absent from a sample row.
- **`subject_parent` is an additive wire field.** An older daemon refuses a session sample with it; the intake drops and counts the batch, and the raw file still holds the data. Activation restarts the daemon with the intake, so the window is the activation itself.
- **`config explain` learns one dotted level** (`config explain bot.telemetry.enabled --bot B`, `bot.telemetry.content`, and whatever `_STRICT_MAPPING_FIELDS` registers next); the whole mapping stays "unsupported", as a mapping has no single origin.
- **`session.active_time_s` is enrichment only** (Claude-only; busy % is `bot.heartbeat`'s); a subagent's spend may land under its own `session.id` (C11).
