## Summary

Two PR legs, in this order. **PR P2-b (S, first, independent)** stops `bot-vitals.sh` emitting `tool_call` (~84 % of
system-event volume, `claudlobby/plane/retention.py:84-87`), leaves the `session_event` removal to the in-flight
#2140 branch it rebases on, and fixes #874's `${BOT_DIR:-${PWD}}` fallback in the same file; it needs nothing from the
Collector or the intake, and its one evidence need — C6's "does OTel cover every `tool_call`" — is the 24-hour overlap
sample on one bot from P0's Claude batch, recorded in the PR body, not a week-long canary. **PR P2-a (L, after; held on
A-F4)** buys the intra-session layer per F3(b)/F4(c)/F5: a `telemetry` mapping in `fleet.yaml` composed into an armed
Claude bot's `bot.conf`; two dormant `unit: service` host jobs (`otel-collector`, running operator-installed
`otelcol-contrib` on a composer-rendered config, and `plane-otel`, a stdlib OTLP/JSON intake that translates a
seven-item allowlist into `emit_batch` batches posted to the daemon's socket through `daemon.send_batch`); the
`config plan` refusal for an enabled bot on a host with no enrolled Collector; the derive-not-mint rule for `session`
subjects; registry, switch and doc rows; then the one-bot, one-host, one-week canary on an independent canary root
and the design v2 §9b decision on its evidence. Deliberately left to others: Codex composition (`[otel]`, F11, the
companion) **and the Codex intake leg** (OTTL statements, resource rule, fixtures — a follow-up after the P0 Codex
batch, C1–C5), traces (none composed, §2.3), and any reader UI over `session.*` samples.

@dataclass(frozen=True)
class TelemetryConfig:
    enabled: bool = False          # STRICT bool (#2145 F4): the arming knob
    content: str = "metadata"      # metadata | full — KNOWN_TELEMETRY_CONTENT

def _parse_strict_mapping(raw: Any, where: str, fields: dict[str, Callable[[str, Any], Any]]) -> dict:
    """One tier's strict mapping → the fields it SETS (absent keys stay absent so the merge inherits
    them; `null` unsets, so `content: null` inherits). Unknown keys are refused by name."""
    if raw is None:
        return {}
    raw = _shaped(f"'{where}'", raw, dict, "{" + next(iter(fields)) + ": …}")
    unknown = sorted(str(k) for k in raw if k not in fields)
    if unknown:
        raise ValueError(f"'{where}': unknown key(s) {', '.join(unknown)} — accepted: {', '.join(fields)}")
    return {k: parse(f"{where}.{k}", raw[k]) for k, parse in fields.items() if raw.get(k) is not None}

def _merge_fieldwise(cls, defaults_raw: Any, bot_raw: Any, name: str, key: str, fields: dict):
    """Field-wise: bot over defaults over built-in (observability's precedence, isolation's strictness)."""
    return cls(**{**_parse_strict_mapping(defaults_raw, f"defaults.{key}", fields),
                  **_parse_strict_mapping(bot_raw, f"bots.{name}.{key}", fields)})

_TELEMETRY_FIELDS = {
    "enabled": lambda where, v: _strict_bool(f"'{where}'", v),
    "content": lambda where, v: _parse_enum(where, v, KNOWN_TELEMETRY_CONTENT),
}

## Stated limitations

- **The `file` exporter is alpha.** Its rotation keys are the only retention knob (`--retention-days` → `max_days`; `max_backups: 15` bounds the sink at 1,920 MiB); a future rename breaks the rendered config at `otelcol-contrib validate`, which the required CI leg catches at the pinned version and the golden comparison does not. `otlphttp` and the `otlp` receiver are stable.
- **Codex composition is the companion's (F11), and the Codex intake leg is deferred.** This PR renders the Claude OTTL statements only and cuts no Codex fixture; the Codex statements, the `codex_cli_rs` resource rule and the Codex intake cells are a follow-up after C1–C5 have run on an installed Codex. A Codex session carries no bot (`fleet = "_host"`, no `subject_parent`) until the companion stamps `[otel] environment = "bot:<fleet>/<bot>"` (C5), and `metrics_exporter = "none"` + `[analytics] enabled = false` are the companion's lines (§11).
- **No traces.** Nothing is composed to export them (beta on Claude Code, undocumented on Codex; §2.3); the envelope's `trace_id`/`span_id` stay unwritten.
- **The intake keeps no cross-window state.** A restart loses at most the open windows (a clean stop flushes them); a session's total is `SUM(value)` with that bound stated in every `METRIC_NAMES` description; a `tool_failure_streak` straddling two windows is two shorter runs and may not be reported; a late record for a flushed window is counted, not recorded.
- **The semconv pin is a commit, not a release** (the GenAI conventions repository has no tag). F5's attribute names stand; a rename is absorbed in one file, and `METRIC_NAMES`/`SYSTEM_EVENT_SEVERITY` are the reader surface that does not move. **Held:** amendment A-F5 (epic §16) proposes no pin and no OTTL at all — an intake-internal mapping over vendor-native raw files; this limitation stays until the operator rules.
- **`subject_parent` is an additive wire field.** An older daemon refuses a session sample with it; the intake drops and counts the batch, and the raw file still holds the data. Activation restarts the daemon with the intake, so the window is the activation itself.
- **`config explain` learns one dotted level** (`config explain bot.telemetry.enabled --bot B`, `bot.telemetry.content`, and whatever `_STRICT_MAPPING_FIELDS` registers next); the whole mapping stays "unsupported", as a mapping has no single origin.
- **`session.active_time_s` is enrichment only** (Claude-only; busy % is `bot.heartbeat`'s); a subagent's spend may land under its own `session.id` (C11).
