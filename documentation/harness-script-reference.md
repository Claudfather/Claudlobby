# Harness script reference

What each instrument in `harness/` does and how, its flags, outputs and measurements, and its history: the reference text of the "Script reference" table in [`harness/CLAUDE.md`](../harness/CLAUDE.md), moved here word for word. A row here holds what the same script's row there does not, in the same order. The rules stay there; this file adds none.

| `harness/ab-comms-eval.sh` | #729 stage-C A/B comms-eval harness (scaffolding) — also hosts the `--experiment coverage-honesty` mode (#866): guardrail-clause variant axis with a run-blocking composed-diff-equals-clause assertion, headless real cells — runs the same comms-heavy battery against two identical bots differing only in `protocols: [token-efficiency]`, composed by real `generate`, and sums the two gated axes (`protocol_sensitive` + labeled `cost_weighted_total` estimate) per variant via `claudlobby.transcript_usage`. Wrapped by `tests/test_ab_comms_eval.py` |

| `harness/ab-recoverability-scorer.py` | #881 A2 recoverability axis — the anti-lossy guard on the routing eval. Per message pair, scores whether a standard follow-up returned the compressed-out detail **in full and unre-summarised** (a shorter summary of the summary is a FAIL — A2 is the empirical gate on `token-efficiency`'s "an explicit request is never re-summarized"). Standalone stdlib module (`ab-comms-verdict.py` precedent); `--dry-run` drives the real scoring logic on synthetic inputs at zero cost |
| `harness/ab-recoverability-judge.py` | Per pair, scores whether the follow-up returned the withheld detail `in_full` and `unre_summarised` — two independent booleans, because a response can be complete and still re-summarised, which still fails. Balanced 5/5 fixtures keep a constant-answer judge at 50% |
| `harness/validate-bot-change.sh` | Empirical validation harness for bot behavior changes. Scored instead, a check expecting a row fails with no reason given, and a check expecting ABSENCE passes. Wrapped by `tests/test_validate_harness.py`; its readers, lifted verbatim, by `tests/test_validate_harness_reads.py`. `VAL_REAL_CLAUDE=<a Claude Code binary>` opts in to real, credential-less boots of the one-prompt start at the 80x24 pane start-bot creates, read from the session transcript (#2669; `VAL_REAL_CLAUDE_RUNS`, default 4) |
| `harness/coldstart-harness.sh` | Mechanical half of the cold-start simulation — `prepare` exports a history-free tree via `git archive` (never a clone) and snapshots the host; `reap` tears down everything the run created; `status`/`transcript` inspect and harvest. Design is **instrument-and-reap, not fence**: a blind run cannot be told "do not enroll supervision" without revealing that supervision exists, and the escape is usually the finding. |
| `harness/freshbox-boot-gate.sh` | #644 P4 real-boot gate — boots a scoped bot on a fresh empty `CLAUDE_CONFIG_DIR` (auth+trust seeded before first contact) and asserts the composed perms hold: clean boot, zero prompts, transcript ⊆ allow. |
| `harness/boot-strand-sampler.sh` | #843 real-boot STARTUP_PROMPT strand sampler — N genuine `claude` boots of a disposable MCP-parity probe through the real `start-bot.sh` injection path (freshbox sibling; `validate-bot-change.sh` stubs the binary, so it cannot measure this). Probe is a declared tokenless canary (`EXPECT_NO_TOKEN=1`) — injects earlier than production's poller-gated READY, at-least-as-hard on the send race; per-boot process trees evidence parity. Summary via `boot-strand-summary.py` (stdlib): exact Clopper–Pearson interval printed next to the n=4 pre-fix baseline. The sampler's `generate` runs with `PLANE_EMIT_ENABLED=1` so the plane exists under the probe root before boot 1. `--model M` sets the probe's model, since every clean boot spends a turn on the account it borrows. `--resume` seeds a fresh handoff before each boot, so `start-bot.sh` takes the resume path: the resume command, then STARTUP_PROMPT typed into the turn that command starts. A boot whose `startup.log` shows no injected resume command is `other:resume_not_injected`, and a prompt queued but still undelivered at the deadline is `other:queued_undelivered`. `--minimal-plugins` copies only what the probe loads from the host plugin cache (its registry files, marketplaces and enabled plugins) instead of the whole cache, and the first boot prints a fingerprint of its skills, SessionStart hooks and MCP servers to compare with a full-cache run. |
| `harness/send-size-probe.sh` | #1493 pane-send size probe — how much of an N-byte payload actually REACHES the reader, through the real `pane_send_verified`, with the transcript as ground truth (`boot-strand-sampler.sh` sibling; the stubbed `claude` `validate-bot-change.sh` uses cannot exhibit a pty race). Arms are INTERLEAVED (reps outer, arms inner) so both share the same minutes of host load; `--arm unchunked` drives the same door with `PANE_SEND_CHUNK_BYTES=0`, the pre-fix shape byte for byte. Measured on macOS 15.7.4 / `claude 2.1.263`, n=3: chunked 21/21 whole at 500-4200 bytes; unchunked 6/6 whole under 1024 and 2/15 over it. Filler is positional by default (it localises a loss); `--filler repeat` keeps the one-character shape that trips a SEPARATE, recipient-side defect — the TUI drops a chunk when consecutive chunks are byte-identical, needing ~1800 identical bytes that a dispatch body does not contain — recorded rather than fixed. **#1876: it records which bytes arrive framed as a paste** — the `pasted` column (start-end payload offsets per `<pasted_content>` block, `-` for none), the verdict taken on the unframed bytes, and `capN` arms for any chunk size. Its receiver is seeded with `tengu_virtual_pancake`, the server-assigned flag that makes the TUI frame a paste; an unauthenticated session never fetches it and frames nothing. Measured on the Pi (`claude 2.1.281`): a burst is framed when one `read()` delivers 801 bytes or more, whatever the box already holds. Wrapped by `tests/test_send_size_probe.py` |
| `harness/rehearse-staged-claude-update.sh` | The #1768 canary for the STAGED claude-update, with REAL npm and the REAL package against a THROWAWAY root (`rehearse-*` family). Normal arm A (staged, verified, linked, no sudo — a recording sudo shim that fails sits first on PATH), then a real credential-less claude session started THROUGH the link, then normal arm B moves the link while that session runs: the session must still be alive, its `/proc/<pid>/exe` must still name A, and its own bash mode (`!`) must still report `CLAUDE_CODE_EXECPATH` = A and run `rg` — on a host with no system `rg` and a throwaway session HOME, only its own binary can answer. Then the stub arm: npm with `--ignore-scripts` reproduces the 2026-09-23 500-byte stub on demand, and the verify must fail, the link must not move, the stub must never become a version, and the alert must fire (to a recording `tg-post` under the throwaway root). Gated on `REHEARSE_STAGED_UPDATE_REAL=1` (~700 MB of downloads, ~5 min on the Pi); needs `/proc` |
| `harness/rehearse-plane-durability.sh` | vera's four checks: loss-witness, WAL-bound, durability-window, service-time. **The traffic is ACCEPTED**: a refused request returns before `emit_batch` calls `connect()`, so it cannot pay the checkpoint, and the issue's original p95 measured refusals and is struck. `--no-reader` is the attribution arm for the held-reader hazard — one arm cannot tell "the reader blocked the checkpoint" from "the daemon never checkpointed". **`--release-after S` (#1905)** lets the held reader go S seconds in: `plane doctor` is read while it still holds (its `wal` rung must name the reader's pid), and the WAL must be back under the 4 MiB ceiling within 10 s of the release. |

| `harness/rehearse-permissions-ladder.sh` | #970 single-factor permissions ladder — the controlled rerun after two days of measurement produced three models and three retractions, because every cell had varied several fields at once. ONE flip per cell against a pinned baseline on a disposable bot, so a result attributes. `rehearse-*` family sibling |
| `harness/plane-parity.py` | Parity between an ARCHIVED JSONL ledger and the plane's rows — once the dual-write canary's verdict instrument, now a reconciliation door for an archive (the F18 closure left no live ledger) — the GENERIC instrument (any ledger, any id field, any table); (the operator's door that once baked in the estate's ledgers, the source-only Plane parity instrument, went with the F18 closure, R3 — there is no ledger left to reconcile; this generic instrument stays for an archived ledger). |
| `harness/naked-bot-observe.py` | #1168 Phase 3 gate: compose a fleet that declares NOTHING and record what a bot receives anyway. `--baseline` re-derives the same observation at a later commit and exits 1 naming each changed (arm, entity type), so a Phase 2 `DEFAULT_*` shows up as a delta rather than being argued about in review. **Records the two surfaces SEPARATELY** — a skill symlink that composes no instruction is a different outcome from one that adds a section, and only reading the composed `CLAUDE.md` distinguishes them. Two of twelve types (`mcp`, `permissions`) write into a file a naked bot already has, so those get a **content probe**; a path-only inventory would report "no change" for a default landing inside one — the blind direction that reads clean. The tree is EXPORTED (`git archive`, `coldstart-harness.sh prepare`'s mechanism minus the host snapshot, since no bot is spun up) for two independent reasons: a checkout under a bot's `projects/` sits inside `…/runtime/bots/…`, which `path_audit` matches as fleet-owned by SHAPE so `generate` fails on a well-formed bot; and a gate must observe a named ref, not an uncommitted tree. Findings and the recorded baseline: `documentation/naked-bot-observation-gate.md`. Wrapped by `tests/test_naked_bot_observe.py` |
