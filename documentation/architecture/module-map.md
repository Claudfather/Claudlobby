# Python module map

Every module in `claudlobby/`, what it owns, and the rules behind it. Moved verbatim from
the root `CLAUDE.md` in #2035, which keeps only where to start. It lives here rather than in
`claudlobby/CLAUDE.md` because Codex reads that file on its way to
`claudlobby/_runtime_scripts/`, within one 32 KiB budget.

```
claudlobby/
  __main__.py         — Thin CLI entry point (~55 lines); argparse setup + subcommands live in commands/
  commands/           — argparse registration and command facades. Canonical task writes live in `task_write.py` over `task_operations.py`; task nudge commits a task fact plus a linked request before notifying the selected fleet manager. `task_recheck.py` owns canonical fleet attention and the private timer entrypoint; The old `commands/task.py` entrypoint is retired; a person's deadline-less assignments are disclosed standing goals, and due rows go to the current fleet manager. `brief_read.py` and `inbox_read.py` read the active fleet through the shared result envelope; they do not acknowledge reports. `checkins.py` resolves `checkin_dispatch` through `TASK_STATUS_SQL`; unknown assignments read `unjoined`, not `open`.
  plane/              — The observable plane: one append-only SQLite flight recorder per host (`state/plane/plane.db`), the typed families and their contracts, minted identity, the write spine (`emit_api.py` → `ingest.py`; the socket daemon `daemon.py` owns INGEST AND NOTHING ELSE; `spool.py` is its cold fallback), the Lane-C derivations (`queries.py` is the one definition of each; `presence.py`, `utilization.py`, `inventory.py`, `orgchart.py`, `expiry.py` are pure reads), the registry lane (`registry_emit.py` at generate, `registry_read.py`), the fleet-event row (`fleet_events.fleet_event_request`, the one Python spelling of bash `emit_fleet_event`'s row, parity-pinned; #2145), retention (`retention.py`), the operator plane (`view.py`, the `[plane-ui]` extra, read-only by construction; `sampler.py`), the unexposed owner-read policy foundation (`owner_access.py`, explicit separate state; no HTTP/CLI integration), (the F18 cutover doors — `parity.py`, `legacy_import.py`, `cutover.py`, the shadow — went with the closure). Backs `commands/plane.py` — `claudlobby plane {emit,emit-batch,status,doctor,serve,view,open,schema,spool,registry,prune,expire}`. **The reference is `documentation/architecture/observable-plane.md`** — the families and the envelope, identity, the write spine and its ladder, every door and its arming carrier (the generate-time registry scan is an opt-OUT since chunk N — it runs unless the fleet-tier `.env` resolves `PLANE_EMIT_ENABLED` to exactly `0`; the runtime doors are always on since F18 R1, and `PLANE_EMIT_DISABLED=1` — carried onto fleet timer units and into `bot.conf` by the composer — is the one silencer); `fleet.yaml env:` reaches only `bot.conf`), the read side and explicit schema migration (`host activate` owns schema changes through the shared migration owner; normal diagnostics and writers refuse an unprepared schema), the cutover as history (the closure deleted its machinery), migrations and retention. The per-chunk design record (why each seam is shared, what each live run measured) lives in the CHANGELOG and the cutover walk `documentation/plans/2026-09-02-plane-cutover-f18-design-walk.md`, not here
  config.py           — fleet.yaml parsing, BotConfig/FleetConfig dataclasses; `load_host_jobs` applies THIS host's override of `host.jobs` (`~/.config/claudlobby/system.yaml`, per job and per field, #1251) so host-local config never lives in the tracked tree; `FleetConfig.leaf_manager_bots()` (PR 4 chunk 4) is the second detectable role — a manager with at least one IN-FLEET report that is not itself a manager, a cross-fleet `manages:` target never counting toward it (F5, ruled)
  known_values.py     — Known-good value sets for fleet.yaml fields (SSOT for config + validator)
  defaults.py         — Compositor-side defaults registry for library entity types (#1168): `REGISTRY`/`Disposition` declare each type's tier and members, `resolve()`/`available()`/`resolve_exclusions()` apply per-fact availability gates (e.g. vault-wired vs hand-scanned shared docs); `Disposition.roles` layers a role-scoped default on top of the global entries, resolved as their union — the `leaf-manager` role overlays the `checkin` protocol onto `protocols` (PR 4 chunk 4), reached only by a bot `FleetConfig.leaf_manager_bots()` names, and the `manager` role overlays the `status` skill onto `skills` (#2010), reached by every bot `FleetConfig.manager_bots()` names (`composer.default_roles` is the one derivation of a bot's roles for both); `config.py` re-exports `DEFAULT_GUARDRAILS` from here rather than declaring its own. See `documentation/naked-bot-observation-gate.md` for the phased rollout and which entity types still have no opt-out
  composer.py         — CLAUDE.md/bot.conf/.mcp.json/systemd unit generation
  boot.py             — BootPolicy: the boot admission/readiness policy (#1573) defined once, from the package `host.boot` section, and rendered into every bot's `bot.conf`
  supervision.py      — `SupervisionSpec` behind both unit renderers (#1573): the one place `bot`/`fleet`/`paths` are read to build a supervision spec, pinned by a round-trip test that parses each rendered unit back and asserts it equals the spec that built it
  mcp_resolve.py      — MCP fragment ${VAR} env-var / instance resolution (shared by composer + validator)
  tool_resolve.py     — Library tools manifest/template/param resolution (shared by composer + validator)
  loader.py           — Library file loading, frontmatter parsing, heading demotion
  validator.py        — Fleet validation (env vars, MCP refs, scope checks)
  skill_refs.py       — Backs a `generate`-time warning: scans composable `library/` content for backtick `` `/name` `` skill references that don't resolve to an invokable skill (#1253)
  newbot.py           — Interactive bot scaffolding wizard
  newskill.py         — Skill directory scaffolding
  newguardrail.py     — Guardrail file scaffolding
  prompts.py          — Shared interactive prompt helpers for the scaffolding wizards
  diff.py             — Drift detection and promotion
  dotenv.py           — .env file handling
  paths.py            — Path resolution helpers
  doctor.py           — Pre-flight fleet health diagnostic
  freshbox.py         — Fresh-box self-containment audit (#644 P4): over-grant/orphan + under-grant + Tier-A composed-not-inherited; deny-by-default rungs (#703): denied source values, externals report + unused-declaration WARN, fleet-tier .env guard, rendered tools/ (backs `claudlobby config validate --runtime`)
  status.py           — Fleet health dashboard (tmux/systemd/fleet-state + the plane: the newest `bot.heartbeat` sample per bot for heartbeat/pane state through presence's own `LATEST_HEARTBEAT_SQL`, and the heartbeat series behind the utilization columns — F18 R2b, keepalive.log is gone; a plane that cannot answer renders those columns `unknown`, flags health `?`, says why under the table and in `--json`'s `plane_unreachable`, never blank-as-healthy)
  uptime.py           — Per-bot uptime (the share of observed time, beside the share observed: #891), MTBR, restart-rate metrics from the plane alone (F18 R2b): the (instant, state) pairs are the heartbeat samples, the dead-session fact (DOWN) and the `keepalive_restart` events (`plane-readers.keepalive_entries`, `entries_from_plane`) through `aggregate_fleet`'s now-required `entries_for` seam; the keepalive.log parser went with the file; `claudlobby fleet uptime` refuses (rc 3) when the plane cannot answer, never an empty table
  utilization.py      — Fleet utilization rollup — per-bot busy/idle % over rolling windows from the plane's heartbeat series (`plane/utilization.heartbeat_series`, the ONE reader shared with the operator plane's surface; F18 R2b): `compute_bot_utilization` takes a bot's (instant, state) series, `compute_fleet_utilization` opens the plane for the fleet and raises `PlaneUnreachable` rather than rolling up zeros
  path_audit.py       — L1 path/grant provenance audit (source-side ownership + external_paths)
  conformance.py      — L4 conformance gates (rename-map drift, boundary invariants)
  workstreams.py      — Plane registry read formatting and current blocked-wait projection; `workstream_operations.py` owns mutations
  brief.py            — Read-only composed fleet state: mission, canonical work, workstreams, unacknowledged reports and recent alerts. `claudlobby --json brief [--bot BOT]` uses the shared schema-1 command envelope with schema-2 brief data. The generated bot is the default viewer; an operator defaults to the selected fleet manager, disclosed in the result. Manager work includes all open fleet-owned tasks, including queued work regardless of who filed or assigned it; a worker view selects current assignments by UID. `work.items` carries canonical task/assignment IDs and separately labeled native deadline/progress/restart observations; `work.issues` and `degraded` disclose unresolved or unavailable evidence instead of a false all-clear. Reports, alerts and workstreams reuse their existing Plane readers. Unacknowledged report rows are the fleet manager's (the oldest 50, a cut labeled); any other viewer gets their count and the `fleet reports list --unacknowledged` command (#2159). The text and bounded `--boot` view preserve unknown-state and truncation disclosures. Current escalations are in `fleet inbox`; reading either surface never acknowledges reports. Acknowledgement is the separate `fleet reports ack` operation over a served-prefix cursor.
  env_tiers.py        — The `.env` tier cascade as the compositor sees it: asks `claudlobby/_runtime_scripts/env-tiers.sh` (`env_tier_rows` in `lib-common.sh`, the same order `start-bot.sh` sources at boot) rather than re-implementing precedence in Python, so a tool can't silently disagree with the runtime about where a secret comes from (#1226). Consumed by `credentials.py` and `env_register.py`
  credentials.py      — Credential reconciliation (#1104): declared vs stored vs equipped-bot. Answers **shape 1** (declared, no value) and **shape 2** (value, no equipped consumer), and **deliberately refuses shape 3** (a declaration and its consumer naming DIFFERENT keys), which is what actually bit the estate — a valid Railway token in a fleet `.env` nothing read, a dead one ambient that `creds-check` read, and the real consumer reading `~/.railway/config.json`. Shape 3 is a property of a PAIR spanning the claudlobby/plugin boundary, and `CLAUDE.md`'s own rule governs it: *consume siblings by contract, never by assertion*. Grepping the plugin tree to learn what it reads is assertion — correct today, silently wrong the next time the plugin changes its read path, with **no signal at the moment it turns wrong**. So shape 3 emits `UNKNOWN — no consumer contract published for <integration>` as a **printed and counted first-class result**, and the summary always carries an `unknown=` count plus "This is a gap, not a pass": a validator that silently omitted it would be indistinguishable from one that checked and found nothing, recreating the bug inside its own remedy. The seam it resolves through is `consumer_contract:` frontmatter, named here so the consumer-end half of #1104 has a target rather than an invention. **Declarations come from `mcp_resolve.required_vars`, never a private scan** — the first version regex-scraped `${VAR}` and reported `TOKEN` unsatisfied on the live estate, when the contract scopes it per instance to `NOTION_TOKEN`, which was present all along: a hand-rolled reader manufacturing a false FAIL inside the tool built to end false FAILs. Tier resolution goes through `Paths.env_resolved`, the same four-tier cascade the runtime reads, so a value stored only at the host/root tier is not falsely reported absent. Present-but-empty is distinct from absent, and an empty later assignment blanks an earlier real value. `UNKNOWN` alone never exits nonzero — a disclosed gap is not a defect, and failing on it would train operators to suppress the check and lose shapes 1 and 2 with it. **No credential value is ever emitted**, only key/presence/tier. Backs `claudlobby host credentials reconcile`; wrapped by `tests/test_credentials.py`
  env_register.py     — Backs the environment-key half of `claudlobby config explain [KEY]`: the DERIVED credential register (#1214 F6 / #1226) — every declared var, the tier it resolves from, and what it shadowed (a value resolving empty from a more specific tier while a real value sits upstream). Fleet/bot scalar origins use the config loader's selection seam. Neither path emits values
  claude_version.py   — The Claude Code version as the compositor sees it (#1772): it calls `claudlobby/_runtime_scripts/claude-version.sh` and carries its verdict, a version or the reason there is none, and never keeps a second copy of the reader or a stand-in string. The registry scan records `claude_version: null` with `claude_version_unmeasured` beside it, and the host contract refuses anything but X.Y.Z or that pair
  switches.py         — THE SWITCH REGISTRY (chunk N): every knob the shipped system has, declared once. **The rule: a job or door is ON by default unless it deletes data, spends money, mutates operator source, or sends outbound to people at scale**; whatever stays opt-in is NAMED where the operator looks, with the one line that arms it. The reason is not caution about defaults — it is that a behavior nobody can see is a behavior nobody has: a dozen doors shipped dormant, each for a defensible local reason, and the composite was a system whose advertised workflow ran nowhere unless someone had read a dozen source comments. Four switches stay off and each states which category keeps it there (`update-siblings` mutates source, `session-digest` spends, `code-audit-sweep` spends + posts, `weekly-worker-restart` bounces live sessions — the stated fifth category, since durable context is what this system exists to keep). Polarity is a FIELD, not a convention (`opt-out` / `opt-in` / `silencer`), and only an exact `0`/`1` decides — an empty assignment wins at its tier (#1213) and is not a `0`, which the shell gates, the composer and this module all read the same way. Every consumer DERIVES: `composer.FLEET_JOB_ARMING`/`HOST_JOB_ARMING` (which unit carries which `Environment=` line — and post-flip it is the **`0`** that must reach a closed scheduler env, #1383 inverted), the validator's dead-flag warning (a `*_ENABLED` key in one of OUR namespaces that no switch claims is DEAD — the namespaces are derived too, so a fleet's own `MYTOOL_ENABLED` stays quiet and a door deleted tomorrow warns without a new list), and the rendered switch tables (`claudlobby host doctor --switches`, `plane doctor`, and the generated schema tables). `status`'s header names any REACTION door that is off, scoped to the three that change whether anything happens at all — a header listing every knob would be scrolled past, which is the same failure as saying nothing
  source_state.py     — The unreachable-vs-empty rule, decided once (#1216/#1014). **A reader that cannot reach its source must not return the same thing as a reader that found nothing** — those two answers have opposite remedies ("wire the instrument" vs "there is genuinely no work") and collapsing them fails toward *everything is fine*, the direction nobody audits. The line is **presence, not emptiness**: a ledger that exists holding zero rows is legitimate and "nothing matched" is TRUE for it; only absence or an IO failure makes that answer a fabrication. Extracted because the rule was already implemented twice, differently, and missing three times — `brief.py` probed and OMITTED with a `degraded[]` entry (right for a composite door whose other sections stay sound), `events`/`uptime` printed and returned 1 on an unreachable bots dir (right for a single-source command), while `report-back`, `workstreams` and `dispatch-overdue --orphans` returned a clean empty answer at rc 0. Three expressions of one rule is how the fourth reader gets it wrong. What is shared is the **classification and the wording**, never the parse — the sources are JSONL, JSON and text logs, so each caller parses its own format and picks its own remedy. `probe_source` tests **openability, not `is_file()`** (a file that stats fine and then raises is the mode that takes out a read door, and a stat-only probe certifies it), and classifies a directory-where-a-file-belongs as ABSENT rather than unreadable, because `IsADirectoryError` is an `OSError` and the naive ordering sends someone to run `chmod` on a path that is simply not a file. **Where the disclosure goes is the caller's, and it varies by consumer — measured, not stylistic**: `dispatch-overdue.py`'s stdout is PARSED (`fleet-pulse.sh:142` reads it into an orphan cache; `report-back.sh:117` pipes `--open` through `awk '{print $3}'`) so a line printed there becomes a phantom row and the refusal rides stderr + rc, while `claudlobby fleet reports list`'s stdout is a human table nothing parses and a stderr-only disclosure is exactly what hid #1216 for a day. `--json` flips a command's stdout to machine-facing, so the disclosure moves to stderr there too. **rc always carries the refusal; the text goes wherever stdout is not machine-parsed** — rc alone is invisible to a human at a terminal, a stdout line alone is invisible to a script. It never raises: a read door that crashed would trade a false all-clear for an outage. `brief.py` aliases these literals rather than redefining them, since they are emitted verbatim in its schema-1 envelope. Wrapped by `tests/test_source_state.py`
  claudron_compat.py  — Claudron compatibility floor — min capability per integration surface
```
