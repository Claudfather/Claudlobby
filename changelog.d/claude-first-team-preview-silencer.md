### Fixed — First-team setup from the setup page: Preview no longer refuses under the guide's own silencer

On a computer prepared from the browser, the first real Preview after a Claude sign-in failed with "Could not prepare the preview, so nothing was saved." The update record showed why: first-fleet setup refused at its prepare stage because `PLANE_EMIT_DISABLED=1` was set in the command's environment. Nobody had exported it. The owner guide's own fixed Linux environment carried that switch, the listener it starts inherited it, and the update's prepare stage inherited it from the listener. First-fleet setup refuses under that switch on purpose (#2611), so a Preview from the browser guide could never pass on Linux. The guide's fixed Linux environment no longer sets the switch. Preparation still does, and nothing the guide runs by itself records to the plane. An operator who exports `PLANE_EMIT_DISABLED=1` in a terminal is refused exactly as before, and the update job that Launch dispatches still takes its environment from the native service manager, not from whoever dispatched it. On a Mac the guide still takes the switch from the managed runtime's environment, so a browser first-team Preview there is still refused; that path is unchanged here.
