### Changed — the heavy slot's memory stop keeps the host's own bounds, and has one off line (#2790)

A plain `heavy-slot.py run` and a render could be left with a stop that never acts: a `stop_mib` far under any reading the host gives before it runs out of memory, or a debounce, poll or grace so long that the stop comes too late to help. The bounds are now host config, in the same files as the lines: `state/heavy-slot/run-lines` holds `stop_mib_floor` (the smallest `stop_mib`), `notice_within_s` (the longest `debounce_reads` x `poll_s`) and `stopped_within_s` (the longest notice plus `grace_s`), and `state/heavy-slot/render-lines` holds the first two, where a render shares a line with a plain run. A file whose values break its bounds refuses every plain run, or every render, at exit 2, the way an unreadable file does; `status` names a `run-lines` file it refuses. The stop stays on by default. Its one off is the line `stop = off` in `run-lines`, which every run then announces on stderr and in its `heavy_slot_acquired` event; no number turns it off, and any other word for `stop` is refused. With no file, `RUN_LINES` and `RENDER_LINES` hold the primary host's numbers (stop line 3800 MiB, floor 3000 MiB, notice within 6 s, stopped within 21 s) until a design sizes them from each host's own spec.
