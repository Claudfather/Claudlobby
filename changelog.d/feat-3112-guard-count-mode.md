### Added — `public-write-guard.py --count` says how many of a text's lines have a hit on the host's term list, never which (#3112)

`public-write-guard.py --count [FILE ...]`, with standard input when no FILE is named, prints for each input how many of its lines a hit on the host's list (`~/.config/claudlobby/public-write-terms`) touches, read by the guard's own loader: one case-insensitive regular expression per line, with comment and blank lines skipped. It prints no term and no matched line. A check that runs on the host before a write, such as a script reading a squash message before a merge, or a review checked before it is posted, can now ask the guard instead of reading the list itself, where a literal reader such as `grep -F -f` misses every line with regular-expression syntax. It exits 0 when every count is 0, 1 when any is above 0 (an input it cannot read counts as a hit), and 2 when the list is absent or broken, so a caller fails closed. `--check` and the hook are unchanged.
