### Fixed — a send typed into a recipient's box and submitted later can now read `delivered` (#3001)

A send whose text is typed into the recipient's input box but not submitted (native rc 3, for example because a turn was running) is recorded as an `unknown` transmission, and that row dropped the wire proof the transport observed. When the text was submitted later, the receiver recorded its `received` row with its own hash and length, but the delivery join had nothing to compare them with: `message receipt` stayed `received` with integrity `unconfirmed`, and `--wait` timed out (exit 8) on a message that may have arrived whole. The `unknown` row now keeps the transport's `wire_sha256` and `wire_bytes`, and the join reads them when the message has no `pane_submitted` or `carrier_queued` row. A receipt recorded once the text is submitted then reads `delivered` when the text arrived intact, `truncated` when it arrived short, and `altered` when it was glued to text the box already held. This holds whether or not the box showed the text at send time: the bytes went on the wire either way, and only the receiver's own row turns them into a verdict. The row's state stays `unknown`, since the submission is still unproven at send time, and a send with no receipt still has no verdict. A request recorded before this change replays as it was recorded.
