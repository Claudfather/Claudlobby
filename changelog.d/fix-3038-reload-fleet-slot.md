### Fixed — each fleet's copy of the daily plugin reload starts a minute after the previous fleet's (#3038)

On a host with several fleets, every fleet's `reload-fleet` timer started at `03:30:00` in the same second, so the host took every fleet's plugin refresh at once. A calendar job can now declare `slot: true` in `claudlobby/system.yaml`, and `reload-fleet` does: the declared time is the first fleet's, and each later fleet's copy, in the order the anchored interval jobs use, runs one minute after the one before it, under systemd and launchd alike. Only a single plain `HH:MM` or `HH:MM:SS` time moves, wrapping within its day. The timers change at the next `host activate`; the other calendar jobs are unchanged.
