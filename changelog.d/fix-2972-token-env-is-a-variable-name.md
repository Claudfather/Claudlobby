### Fixed — `telegram.token_env` is checked as a variable name at load (#2972)

`telegram.token_env` names the environment variable that holds a bot's Telegram token, and it loaded as written. Since #2970 the daily credential check reads it through the shared declaration walk, which refuses the whole fleet when a declared name is not a shell variable name, so one bot's malformed `token_env` stopped the daily check for every bot in its fleet. The loader now checks it the way it checks `git_credentials` names: a value that is not a shell variable name is refused at load, so at `config plan`, naming the bot and the field, or `fleet defaults` when the value is written there. The refusal does not repeat the value, since a Telegram bot token written in place of a name is refused too. An empty `token_env` loads as absent, which is how every reader of it already treats it.
