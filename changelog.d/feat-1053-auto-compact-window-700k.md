### Changed — bots' autocompact window defaults to 700,000 tokens (#1053)

`auto_compact_window:` now defaults to `700000`, where it defaulted to `auto`. A bot whose entry and fleet `defaults:` set none composes a top-level `autoCompactWindow: 700000` into its `settings.local.json`: the window Claude Code compacts within. Claude Code checks the context between requests and compacts once it has passed the window less its own autocompact buffer (33k tokens in `/context` on Claude Code 2.1.322). With nothing set, a model with a native 1M window compacts within its 1M window: at about 967,000 tokens, Claude Code's docs say. One large step can carry the context past the window before that check, and if the compaction fails ("Not enough messages to compact"), the request still goes out. Claude Code caps the window at the model's own, so a model with a 200,000-token window keeps its own. The bound is a number of tokens, the same on any host, which is why it is a package default rather than a number each host tunes.

`auto_compact_window: auto` turns the bound off and composes what the default composed before: `modelSettings` naming each native-1M model `"auto"`. A `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in a bot's environment still takes precedence over either. Both forms keep blocking Claude Code's offer to "autocompact at 400k tokens instead" (#1388), since a window set in local settings stops it. With a set window, Claude Code's context footer counts "N% until auto-compact" where it counted "N% context used".
