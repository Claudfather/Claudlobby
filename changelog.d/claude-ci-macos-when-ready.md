### Changed — macOS tests run once a pull request is ready for review, not on every push of a draft

A draft pull request now runs the Linux lanes only, until it is marked ready for review, which starts a run with every lane. On a draft the macOS shards and harness read skipped and the gate job is skipped under the name `matrix.macos-not-run-on-a-draft-pull-request`, so a commit carries no `supported (macos-latest, py3.11)` result until a run that ran macOS has judged it. A draft that carries the `macos-on-draft` label runs macOS like a ready pull request; it is meant for an integration branch's own pull request. A pull request opened ready runs macOS on every push, as before, and so does every push to `main`. The account runs five macOS jobs at once and one run uses all five: across the 14 runs measured on 2026-11-21, macOS jobs waited a median of 19 minutes for a runner (up to 40), and a run took a median of 43.9 minutes where its Linux lanes took 18.7. Open a pull request as a draft while you iterate, and mark it ready when Linux is green. Until then nothing has run the change on macOS or on Python 3.11.
