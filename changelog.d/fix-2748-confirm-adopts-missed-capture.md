### Fixed — a start whose SessionStart capture never lands reads ready, instead of waiting out its readiness ceiling (#2748)

A new session's SessionStart hook confirms the bot's native-session receipt, and every start waits for that confirmation: `bot start`, `bot restart` with or without `--fresh`, and a host update's restart of each running bot. When the capture never landed, the wait polled until its readiness ceiling and the start read unverified. The wait's confirm now adopts the launch from the provider's PID record for the pane's process, by the rule the planned checkpoint uses: the record must name the session the receipt retains, at the pane's own process start, and that session must have written its transcript. Anything short of that proof leaves the receipt untouched and the wait polling as before, so a record that contradicts the launch still waits out the ceiling. A launch whose capture missed after its session wrote its transcript now continues that session at its next start, such as a keepalive restart, where it was retried as a new session under the same id, which Claude Code refuses for an id already in use.
