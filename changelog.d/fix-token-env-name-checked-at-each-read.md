### Fixed — `TELEGRAM_TOKEN_ENV_NAME` is checked as a variable name before each read of the token

`TELEGRAM_TOKEN_ENV_NAME` names the variable that holds a bot's Telegram token, and three reads look the token up through it: `start-bot.sh`'s own, the session shell's (the block `start-bot.sh` writes into the bot's `.tmux-env`, which zsh sources on macOS), and `resolve_bot_telegram_token` in `lib-common.sh`, which `bridge_state` and the daily credential check call. Each now checks first that the value is a variable name (ASCII letters, digits and underscores, not starting with a digit, the rule `telegram.token_env` meets at load since #2974), with one `case` that bash and zsh both run. A value that is not one reads no token, as an unset name does, and logs one line that does not repeat it, since a token written in place of a name is not a variable name either: `start-bot.sh` and the session shell each to the bot's `startup.log`, the resolver to its caller's stderr. Before, such a value stopped `start-bot.sh`, and the shell error it printed repeated the value.
