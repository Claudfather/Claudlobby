### Added — on Linux, System tools can make the team's own account, `claudlobby`, or adopt one that conforms

`linux-system-v1.sh` now treats the account `claudlobby` as the team's. A System tools proposal for it carries a `login` block with exactly six keys: `account`, `uid`, `gid` (equal to the uid), `home` (`/home/claudlobby`), `shell` (`/bin/bash`) and `state`. Its disclosure adds what the account is, what it can do and that setup never removes it. When the account exists, `state` is `present` and it is used only if it conforms: a uid from 1000 to 59999 that no other name shares, its own group with no members and no other groups, shell `/bin/bash`, a home `/home/claudlobby` that it owns with no group or other bits, an empty mail spool if any, a locked password with no hash, no forced change, maximum age, inactivity limit or expiry, and no subordinate ids. Each mismatch has its own code (`team_account_uid`, `_group`, `_shell`, `_home`, `_password`, `_expiry`, `_ids`).

When it is absent, `state` is `create`. The uid the browser offers must equal the next id the leaf computes from `/etc/passwd` and `/etc/group` by the readiness probe's rule, run against the same `tests/fixtures/next-uid-rule.json` table, and no account, group, process, user manager or `/run/user` folder may hold it (`team_uid_changed`, `team_uid_unavailable`). A left-over group, subordinate-id line or mail spool refuses as `team_leftovers`, a left-over `/home/claudlobby` as `team_home_exists`, a `passwd` or `group` source in `/etc/nsswitch.conf` other than `files` and `systemd` as `team_directory_service`, and a port 443 that Serve already serves as `occupied_443`, all before anything is proposed. At apply each check runs again, and a team refusal then reads `proposal_changed`, before anything is dispatched. The worker checks the block once more, then runs one fixed `/usr/sbin/useradd` (`--uid N --user-group --create-home`, home `/home/claudlobby` at mode 0700, shell `/bin/bash`, no expiry or inactivity, no subordinate ids, `PASS_MAX_DAYS=-1`) once, before apt and lingering, and checks the result. A non-zero exit (`useradd_failed`) or an account that then does not conform is `failed_partial` with no apt and no lingering; a later inspect adopts the account if it is now present and conforms. Status reports `team_account`: `conforming`, `absent` or `unexpected`. Package-list refreshes work before the account exists; the private route needs it present.

Every other account's proposals are byte for byte what they were, held by a golden copy. When the leaf saves a new record it removes planned receipts whose expiry has passed and keeps every other record. `linux-system-entry-v1.sh` changes only its leaf pin. Nothing a person sees changes until the website pins this leaf.
