### Added — the computer run: a fresh computer to its started services, with no Claude or team card

`host owner setup --stdio-computer` is a fourth mode of the owner guide, reached by the guide script's new `computer` action. On a fresh computer it asks, in order, `prepare_directories`, `initialize_owner`, `pair_owner`, `initialize_link_storage`, `bind_workspace` and `start_workspace`, each only when its step is not done yet; it never asks to install Claude, sign in to Claude or set up a team. Its result is `computer_starting` with the start's `request_id`, `config_fingerprint` and `target` while the updater works, or `computer_ready` with the owner server's origin once the started service answers on its socket. When a start stops, `start_failed` carries the start's own line and its `request_id`. The run never waits for the updater and never continues a record: its process exits before the updater's cutover. A computer with a guided team setup retained, or in any other state, is told `use_full_guide`. Today's `--stdio`, `--stdio-status` and `--stdio-api` modes are unchanged, and a test pins today's guide frame by frame on the typed channel.

### Changed — the computer action may run at a revision a finished update moved to

The guide script's `computer` action takes one more request key, `update_record`, naming a request ID and target. Its source check refuses a checkout whose `HEAD` is not the revision asked for. When the installed revision is not the receipt's, the fixed profile admits it only if the named record is the one on disk, is `done` with no health errors, targets the installed revision, and the receipt's revision is its ancestor; these checks run in Python, not in the shell. Today's `setup`, `status` and `api` actions keep their rule and refuse the new key.
