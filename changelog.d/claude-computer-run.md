### Added — the computer run: a fresh computer to its started services, with no Claude or team card (#3058)

`host owner setup --stdio-computer` is a fourth mode of the owner guide, reached by the guide script's new `computer` action. On a fresh computer it asks, in order, `prepare_directories`, `initialize_owner`, `pair_owner`, `initialize_link_storage`, `bind_workspace` and `start_workspace`, each only when its step is not done yet; after a declined card the next run asks the cards that remain. It never asks to install Claude, sign in to Claude or set up a team. Its result frame is `computer_starting` with the start's `request_id`, `config_fingerprint` and `target` while the updater works, or `computer_ready` with the owner server's origin once the started service answers on its socket. When a start stops, the `start_failed` error frame carries the start's own line and its `request_id`. A start under way is read without a card or a dispatch. The run never waits for the updater and never continues a record: it returns while the start waits at `quiesce`, and once its process exits its reader lease is free for the updater's cutover. A computer where today's guide retains a first-team approval or a Launch, or one in any other state, is told `use_full_guide`; a computer part-way through today's cards with nothing retained is taken over. Today's `setup`, `status` and `api` routes are unchanged, and tests pin today's guide frame by frame on the typed channel, built from its own configuration, and today's error frame keys.

### Changed — the computer action may run at a revision a finished update moved to (#3058)

The guide script's `computer` action takes one more request key, `update_record`, naming a request ID and target. Its source check refuses a checkout whose `HEAD` is not the revision asked for. When the installed revision is not the receipt's, the fixed profile admits it only if the named record is the one on disk, is `done` as strictly as today's finish reads one (an empty health table, out of maintenance, configuration committed, no stage error), targets the installed revision, and the receipt's revision is its ancestor; these checks run in Python, not in the shell. Today's `setup`, `status` and `api` actions keep their rule and refuse the new key.
