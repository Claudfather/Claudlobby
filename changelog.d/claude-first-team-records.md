### Fixed — a computer set up again from the same browser offers Claude sign-in, Preview and Launch, not a dead end

After a computer was reset and set up again, the setup view in the same browser still held the earlier installation's setup request, the computer's word that its Launch was reserved, and its Claude sign-in. It said setup was already submitted, offered only Check launch status, and never offered sign-in, Preview or Launch. Now, when the computer's approval read shows a new approval that holds no request, the view sets the earlier request aside with the conflicting identifiers (still listed under Details; when that list holds 16, its oldest entry goes) and stops following the earlier sign-in. The earlier request's `:launch` record stays in storage but has no effect. Until an approval read succeeds, Check setup approval leads over Check launch status, so a failed first read no longer leaves the refused status check as the only filled button. A computer cannot hold a new approval while it keeps any Preview or Launch (`setup_original_request_retained`), so this never sends a second Launch on the same installation. Under the same approval, a kept request still blocks a second Launch exactly as before. No sentence the view shows changes.
