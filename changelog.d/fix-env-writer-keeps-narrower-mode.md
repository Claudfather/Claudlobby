### Fixed — the private file writer keeps a narrower mode it finds, and a failed folder sync after the rename no longer fails the write

The one writer behind fleet and bot `.env` files and `fleet.yaml` (`migration env --apply`, `fleet setup`, `bot create`, and the compositor's `.env` scaffold when it adds a variable) gave every file it replaced mode 0600, so a file kept read-only at 0400 came back writable. The new file now takes the old one's owner read and write bits: 0400 stays 0400, 0640 and 0644 still become 0600, and a new file is 0600 as before. The temp file is still owner-only from its first byte. A folder sync that fails once the new file is in place is now a warning that names the file, not a failed write, since the file is already live. A failure before the rename still leaves the old file whole and reports the error.
