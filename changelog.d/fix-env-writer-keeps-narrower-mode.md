### Fixed — the private file writer and the `.env` scaffold keep a narrower mode they find, and a failed folder sync after the rename no longer fails the write

The one writer behind fleet and bot `.env` files and `fleet.yaml` (`migration env --apply`, `fleet setup`, `bot create`, and the compositor's `.env` scaffold) gave every file it replaced mode 0600, and the scaffold set 0600 on every `.env` it found up to date, so a file kept read-only at 0400 came back writable at the next write or compose. Both now keep the file's owner read and write bits: 0400 stays 0400, 0640 and 0644 still become 0600, and a new file is 0600 as before. The temp file is still owner-only from its first byte. A folder sync that fails once the new file is in place is now a warning that names the file, not a failed write, since the file is already live. A failure before the rename still leaves the old file whole and reports the error.
