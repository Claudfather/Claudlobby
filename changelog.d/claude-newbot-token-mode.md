### Fixed — a new bot's token goes into a new owner-only `.env`, never into a file others can read

Creating a bot with a Telegram token wrote the token into `.env` in place with `write_text` and only then set the file to 0600. A new `.env` was created with the umask's mode (usually 0644), an existing readable one stayed readable until the write finished, and a process that had opened it earlier could read the token through that descriptor even after the mode changed. Bot creation now writes `.env` the way it already writes `fleet.yaml`, through `_write_config`: a new temporary file beside it, created 0600, flushed and synced, then renamed into place. Other lines are kept in their order. `newbot.write_token_to_env` becomes `newbot.env_text_with_token`, which only computes the file's new text; it no longer passes the token through a regular-expression replacement template, so a backslash in a token is written as is. A write that fails part-way now leaves the old `.env` whole instead of cut short. The new file is owned by the account creating the bot.
