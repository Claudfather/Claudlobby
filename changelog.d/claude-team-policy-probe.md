### Added — as root, the readiness probe rechecks the team account and says whether setup left an operation unfinished

`logins.team` becomes `{"uid": N, "policy": P}` when `/etc/passwd` has a `claudlobby` line, and `logins` gains a fourth key, `uncertain`, beside `team`, `next_uid` and `prepared`. With no `claudlobby` line, `team` stays null with no `policy`, and `uncertain` is still reported. Until now a return visit rechecked the account only through the private connection's approval, which the website will soon skip when the route is already exact; this keeps that check in the read-only step every visit already runs.

`policy` comes from `/usr/bin/python3 -I -S -B`, run as root on a block in the probe that is `linux-system-v1.sh`'s own `team_policy` and every helper and constant it uses (`directory_service`, `sudo_rules`, `team_lines`, `read_root`, `lookup`, `trusted_parents`, `lstat`, `subordinate`, `require`, `Refusal`, `PATHS`, `TEAM`, `TEAM_HOME`, `OWNER`, `LIMIT`), byte for byte; a test holds each definition to the leaf's source, and the leaf is not edited. It reads, and never writes, the account through the system's account lookup, `/etc/shadow`, `/etc/gshadow`, `/etc/subuid`, `/etc/subgid`, `/etc/nsswitch.conf`, `/etc/sudoers` and `/etc/sudoers.d`, and the team home and mail spool's metadata. `P` is `conforms`, one of the nine team codes the leaf refuses a present account with (`team_directory_service`, `team_account_uid`, `team_account_group`, `team_account_shell`, `team_account_home`, `team_account_password`, `team_account_expiry`, `team_account_ids`, `team_account_sudo`), or `unknown`: no Python, not root, a 4-second alarm, any exception, any other answer (including the leaf's `unsafe_parent` and `unsafe_file` file checks), or output that is not one bounded word with a clean exit. One table of cases runs through the leaf's `team_policy` and through the probe end to end.

`uncertain` judges setup's root store the way the leaf's `no_pending` does, in the walk that already reads it for `prepared`, within the same bounds (128 names, 96 KiB each): `true` when a receipt past planned has no recorded end, or is a System tools or index-refresh receipt with no dispatch record; otherwise `null` on doubt (a link, a non-file, a name that is not a receipt UUID, an unreadable or oversize receipt, another shape); otherwise `false`. A receipt the probe cannot read no longer stops the walk for `uncertain`; `prepared` is unchanged. Output stays one line, about 1.1 KB at most. The website must accept both keys before it pins this probe: its decoder today refuses any other key.
