### Added — `bot status` and `fleet status` name the model of each bot's newest call (#2979)

Each bot's `context` in `bot status` and `fleet status` gains `model`: the model that answered its newest main-chain call, from the transcript row that already gives `tokens` and `at`, read in the same pass. A session is launched on the configured model, and a model change inside the session shows at its next call. `model` is null whenever `tokens` is, under the same `reason`, and null as well when that row names no model. Sidechain rows and the zero-usage rows Claude Code writes itself for an error or an interrupt are skipped, as they are for `tokens`. The `bot status` text names the model on its `Context:` line (`model unknown` when the row names none); the `fleet status` table is unchanged. `brief --usage-since` carries the same `context`, so its JSON gains `model` too, and its text is unchanged. Nothing compares the model with the configured one.
