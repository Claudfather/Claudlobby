### Fixed — Claude sign-in from the setup page: the computer can read Claude's reply

A browser sign-in to Claude ended with "Claude replied in a way this computer did not recognize" every time a code was entered, and no sign-in was saved. After the code, Claude 2.1.325 sends a terminal control sequence that switches off a keyboard mode (`CSI > 4 m`). It shows nothing and carries no text, but the computer's reader did not know it and refused the whole reply. The reader now ignores that sequence and its close relatives: the other `CSI > 4 ; n m` forms, and the kitty keyboard protocol's push, pop and set (`CSI > n u`, `CSI < n u`, `CSI = n ; m u`), which programs send at the same moments. Only `CSI > 4 m` has been seen from Claude; the others are accepted so the next one does not end a sign-in the same way. Everything else about the reader is as strict as before, and an unknown sequence is still refused and named in the sign-in record.
