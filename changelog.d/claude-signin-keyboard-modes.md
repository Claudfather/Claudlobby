### Fixed — Claude sign-in from the setup page: the computer can read Claude's reply

A browser sign-in to Claude ended with "Claude replied in a way this computer did not recognize" every time a code was entered, and no sign-in was saved. After the code, Claude 2.1.325 sends a terminal control sequence that switches off a keyboard mode (`CSI > 4 m`). It shows nothing and carries no text, but the computer's reader did not know it and refused the whole reply. The reader now ignores that switch-off, the same reset written out (`CSI > 4 ; 0 m`), and its twin in the kitty keyboard protocol, the pop (`CSI < n u`), which a program sends on the same way out. Only `CSI > 4 m` has been seen from Claude. Sequences that turn a key-reporting mode on are still refused. Everything else about the reader is as strict as before: an unknown sequence is refused and named in the sign-in record, and sequences that begin `CSI <` or `CSI =` are now named there as `csi private ...` where they used to read `csi malformed ...`.
