### Fixed — a first team set up from the website can admit work in its approved folder

A `local-project` team gives each bot a `project` mount: the one folder the person approved. With no `projects.yaml`, the fleet declared no project, so `project show` refused the folder's name and the lead would not admit work until an operator declared it, which nobody using only the website can do. Each distinct folder that a bot mounts as `project` is now a derived project named after the folder, at tier `review`, with no repos, next to the projects derived from `scope.repos`. The lead's Projects table, every `bot.conf` and `host doctor` name the source as `mounts.project`. The setup template, its `fleet.yaml` and the approval are unchanged, and a fleet with no `project` mount composes the same text as before.
