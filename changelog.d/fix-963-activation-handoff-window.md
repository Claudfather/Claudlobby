### Fixed — an activation can keep the handoff a bot saved before it went idle (#963)

An activation stopped each running bot only after a handoff saved in the last 300 s, or one the bot wrote within 30 s of being asked. A handoff is a model turn of minutes, so a bot that had saved and stayed idle halted the run, and each halt needed a `--resume` inside 300 s of that bot's next save. `host activate --handoff-max-age SECONDS` (300 to 86400, default 300) now widens the window for the activation alone: such a bot is not asked for a new handoff, and its capture is verified against the same age when its session stops. The activation records the value and `--resume` keeps it. `bot handoff` and a bot's own restart keep 300 s. During an upgrade the handoff script also reads a saved capture with its own release's interpreter: a bot's configured CLI still names the release being replaced, whose reader cannot answer the script, so no saved handoff counted as recent.
