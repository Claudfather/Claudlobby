### Fixed — A Claude sign-in that timed out or was cancelled before its code was sent now offers Try again, instead of stranding setup (#3020)

First-team setup gives the Claude sign-in a fixed time. When that ran out (a password reset, a slow second factor, stepping away), or the sign-in was cancelled, the panel said the setup allowed only one Claude sign-in. It offered nothing but a progress check, so the whole setup had to be recovered on the computer. The host now records, before it types a code, that a code reached the Claude CLI. It reports an attempt that timed out, or was cancelled (by Cancel sign-in or by a lost connection), with no code delivered as retryable. The panel then says, for example, "The sign-in took too long. Choose Try again for a new sign-in link." Try again starts a new attempt, with a new attempt ID and sign-in link, under the same approval, and is sent only on that click. If the computer refuses it, or it could not be sent, the page keeps following the ended attempt instead of getting stuck. While the Claude tab is in front, the page keeps a read-only check every 25 seconds, so approving at Claude no longer closes the sign-in after 45 seconds. Every other ending keeps the single attempt, including a timeout or cancel after the code was sent, an interrupted attempt and a saved credential. One approval allows at most ten attempts.

Finish or recover setup before downgrading. This version adds two columns to the host's `setup_provider` table when it approves setup or starts a sign-in, and older versions refuse that table until it is recovered on the computer.

### Added — The Claude sign-in step shows the time its code must be pasted by (#3020)

Once the sign-in link is ready, the step says, for example, "Paste the code by 11:50 AM." in the viewer's local time, so the time limit is no longer a surprise. The time comes from the host as `expires_at`, in whole seconds, beside the link: the last moment it accepts a code, 20 seconds before the earlier of the attempt's timeout and the setup approval's expiry. A later code is refused, so a code is never cut off mid-exchange and a late one ends as a clean, retryable timeout. The panel only formats the time and starts no timer of its own.
