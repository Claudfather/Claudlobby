### Fixed — fleet alerts are sent as the fleet manager, not the first bot by name (#3127)

With no escalation pair declared, a fleet alert or notice to the fleet chat was sent as the first declared channel bot in that chat in directory order, so on a fleet whose workers sort before its manager every `FLEET ALERT` and `FLEET NOTICE` came from a worker. The sender is now the fleet manager whenever it is a channel bot in the chat whose channel state dir holds the `.env` its token is read from. When it is not, the first other such bot by name sends, and a line on stderr names that bot and says why the manager did not; when no bot in the chat holds a token file, the manager is still the one picked, and its post fails naming the missing token. One rule picks the sender for fleet-pulse, creds-check (its delivery token too), `emit_failure_alert`, `emit_fleet_notice`, `notify_currency`, `fleet notify` and the alert a failed message write raises. `fleet notify` and that alert now fall back to such a bot when the manager is not a channel bot, where they reached the manager's pane only. `claudlobby config validate` warns `alert-sender`, and doctor's `fleet-yaml` rung names the warning, when the configuration sends a fleet alert as a bot that is not the manager. A declared `fleet_pulse` escalation pair still wins for the alerts it covers, fleet-pulse's and those of `fleet notify` and a failed message write, and so does a chat and state dir set together in the environment.
