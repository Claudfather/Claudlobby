### Fixed — `config validate` warns on a `fleet.sweep.audit_types` entry that `code-audit-sweep` does not run (#2992)

`fleet.sweep.audit_types` was read as a list of strings and exported unchanged, and nothing checked the names. The `code-audit-sweep` skill runs `tech-debt`, `security`, `docs` and `product-enhance`; for any other name it runs no audit and emits `audit_failed`, a notice-level event, on the day the rotation picks that entry, so a manifest that still named the old documented example `security-audit` learned of it only then. `claudlobby config validate` now warns once for each such name, under the new category `audit-type`. It names the type that replaced a name the skill's table listed before it was renamed (`security-audit` is `security`, `docs-review` is `docs`), or else the closest of the four types when one is close, and says that the `data-model` lens, also under its old name `data-model-audit`, runs only by hand. It is a warning and never an error, so an old manifest still loads; `--strict` and `--warn-baseline` count it as they count any warning. The list of types is `CODE_AUDIT_SWEEP_TYPES` in `claudlobby/known_values.py`, and a test pins it to the table in the skill; `CODE_AUDIT_RENAMED_TYPES` holds the three old names, and a test pins each replacement to a type that runs or runs by hand.
