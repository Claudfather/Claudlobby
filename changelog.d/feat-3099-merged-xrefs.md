### Added — the check-in's backlog read lists the merged pull requests that cross-reference each issue (#3099)

`issue-intake.py list` takes `mergedReferences` among its `--json` fields: each kept issue then carries the merged pull requests that cross-reference it, closing or not, by number, merge time and URL, read by one GraphQL query per 50 kept issues. An issue whose work merged under a reference that does not close it, such as `Refs #N`, stays open, and a check-in read it as free work. Step 4 of the `checkin` skill now asks for the field and says what an entry means: a reason to read that pull request's first line before counting the issue as free work, not proof that the issue is done. Without the field, the intake reads and prints what it did before. A failed or malformed reference read refuses at exit 3, as a failed issue read does.
