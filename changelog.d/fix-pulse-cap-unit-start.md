### Fixed — a scheduled fleet pulse counts its cap from its unit's start again, and its stop fits inside the unit's limit (#2604)

A scheduled pulse run is meant to end by its ceiling, counted from its unit's start, but nothing passed that start to the pulse any more, so the cap counted from the sweep's own start. A sweep that started late could run on past the unit's time limit, and systemd then stopped the run before the cap did: the unit failed with result `timeout` and left no stop summary. The native unit entry now passes each scheduled command its unit's start. The unit's margin after the ceiling now covers the CLI's exit after its stop line as well as the stop's grace and reap, and the unit's limit stays 254 s, so the default ceiling is now 233 s (it was 240 s). The stop writes its summary before it copies the sweep's warnings to the journal.
