### Added — Locally approved browser-mediated Claude sign-in

The connected first-team guide can run one explicitly approved, exact-artifact
Claude setup-token attempt on the selected host. It exposes a validated provider
link and private code entry, retains the original attempt without automatic
retry, and stores the token only in the host's private environment file.
Cancellation and interrupted attempts retain uncertainty. Existing private-token
setup and separate local message approval remain available.

After original Launch, the same guide releases its old runtime readers, waits
read-only for that exact update and reenters current source before optional local
messages-only approval. Skipping creates no new approval; interrupted or refused
effects retain their original recovery identity without automatic replay.

Exact supported public Claude artifacts installed with hard links are accepted
through held-descriptor hash and identity verification. Private credentials and
per-attempt executable copies retain their single-link requirement.
### Fixed — Local workspace approval recovery

The first-team guide identifies rejected workspace approval codes without asking
users to pair the owner again. It keeps local serving available for an explicit
RETRY with a new browser proposal, or CANCEL/EOF to stop. Retries preserve the
original owner and workspace binding, show the verified proposal again, and
recheck its validity in the authority transaction when BIND-WORKSPACE is entered.
No proposal, binding, provider attempt or launch is retried automatically.

### Changed — Reusable core workspace approval

Workspace binding now uses a shared read-only preview and explicit presenter
approval, with terminal rendering kept separate. Hidden codes, approval wording,
fresh-code retry and transaction checks remain intact. Owner or binding changes
during code entry now produce a specific conflict. This adds no command,
endpoint or authorization channel; a presenter does not authenticate its caller.

### Added — Passive preinstall host inventory

A standalone, package-owned POSIX `host-readiness-v1` payload reports bounded
OS/account facts and prerequisite executable presence without executing those
prerequisites. Python features, provider sign-in, Tailscale access and native
user-manager readiness remain explicitly unknown. It lives under `preinstall/`
because initial inventory cannot depend on installed runtime helpers; no SSH
transport, setup action or bot-runtime wiring is added.

### Fixed — Stable Ubuntu test qualification

The tests workflow pins Ubuntu 24.04, the previously passing qualification
baseline, after `ubuntu-latest` moved to 26.04 and broke native process and
command-mirror fixtures. Existing check names and artifact identifiers stay
stable; Ubuntu 26.04 qualification remains pending.

### Fixed — Bootstrap commit pin and recovery validation

Git preparation now requires an explicit full-commit ref to equal both its
resolved and retained revision before dependency or stable-entry effects. A
matching full-pin fetch can recover without another fetch; an unexpected commit
is refused with its existing receipt and files retained. An unresolved symbolic
ref is fetched from the explicitly bound remote instead of adopting an unbound
retained FETCH_HEAD. Once recorded, symbolic-ref resolutions remain frozen on
retry, including dependency-preparation recovery.
A receipt with no resolved revision but retained dependency or completion
progress now refuses before installation writes or Git access, preserving the
existing evidence instead of attempting a new resolution.

### Added — Typed local owner guide over stdio

The first-team guide supports a hidden finite ASCII stdio profile for an
authenticated local SSH operator, with separate read-only status. Core-authored
proposals retain exact workspace objects and require session, sequence, digest
and expiry checks. Website login grants no host authority. The fixed Linux
profile uses account-database paths and separately approved directory effects.
If the reviewed Claude executable is genuinely missing, a separate Install
Claude proposal may download its exact public bytes into the fixed private
host directory. Existing canonical bytes are a read-only no-op. Unknown or
foreign results stop without an automatic or same-invocation retry; a later
clean missing target requires fresh explicit consent. Installation performs no
provider sign-in, model work or service start. Native ingress remains a prerequisite.

The guide preserves both temporary servers and existing authority transactions,
captures child diagnostics, and gives its foreground server an inherited
parent-liveness pipe. EOF, cancellation and parent death request normal drain.
After the original Launch it emits only the framed handoff and exits; an exact
healthy-DONE reopen may offer separate optional message approval. Browser
transport integration and native/provider/first-team qualification remain open.

The fixed guide environment retains only its admitted installation and data-root
selectors for uncached source resources. Typed interruption drains owned work and
reports an uncertain stopped outcome for inspection; interrupted provider install
never implies rollback or an automatic retry. Completion reopens require the
original tuple. Retained parent-directory checks allow unrelated activity while
preserving identity and create-only checks; buffered partial frames expire after
the existing five-second limit.

### Added — Bounded root preparation source candidate

A standalone Ubuntu 24 root bundle retains immutable, expiring proposals and
one-shot request receipts for fixed package prerequisites, separately approved
index refresh, selected-account lingering and independent private ingress CAS.
Native apt owns the transaction; a version3 pre-install verifier rejects exact
action/version/architecture drift. Existing root hooks and possible service
changes are disclosed, with local conffiles preserved. A fixed transient worker
retains boot/invocation identity across frontend disconnection; uncertain work is
never replayed or automatically repaired. Serve publication preserves other
routes and Funnel settings with the original nonempty ETag and whole afterstate
comparison. The root-native exception does not change bot supervision or the
mode-specific owner-socket defaults. Browser/root transport integration, native
apt/systemd/LocalAPI compatibility and cold-host proof remain unqualified gates;
this source candidate does not establish usable onboarding or host authority.
