### Fixed — two harness instruments no longer remove the folder they were started in when the disk is full

On 2026-11-21 a test run lost its whole checkout. `harness/rehearse-held-push.sh` and `harness/rehearse-debounce-recipient.sh` made their throwaway root with `ROOT="$(mktemp -d)"` and then `ROOT="$(cd "$ROOT" && pwd -P)"`, under `set -uo pipefail` with no `-e`. With the disk full, `mktemp` failed and printed nothing; `cd ""` succeeds in bash without moving, so `ROOT` became the folder the script was started in, and the exit trap ran `rm -rf "$ROOT"`. pytest starts both instruments from the checkout (`tests/test_held_push_harness.py`, `tests/test_debounce_recipient_harness.py`), so the checkout was the folder removed. Started from a home folder, either script would have removed that. A private `TMPDIR` does not help on macOS, where a bare `mktemp -d` ignores it. `harness/` is not packaged, so no installed computer runs these two.

Both instruments now make their root through the new `harness/scratch-dir.sh`. `scratch_dir` stops the script with exit 3 and "Nothing was removed" unless `mktemp` really made a new directory. `scratch_remove` refuses a path that is empty, relative or the filesystem root, and a directory that is or holds the current directory, the directory the script was started in, the checkout the helper is in, or the home directory. The two test wrappers also start their instrument in a private directory, not the checkout.

Six more scripts had the same unchecked `mktemp -d` without the `cd`. None could reach the start folder, but an empty value pointed their paths at the filesystem root. They now stop when the directory cannot be made:

- `harness/rehearse-env-cascade.sh` exported into `/root` and `/home`, and its exit trap ran `pkill -f "/bin/claude"`. It uses `scratch_dir` and `scratch_remove`.
- `harness/rehearse-plane-durability.sh` took `/root` as its canary root. It uses `scratch_dir` and `scratch_remove`.
- `harness/ab-comms-eval.sh` was stopped only by `set -e`. It now stops by its own test and removes its two directories through `scratch_remove`.
- `tests/test_alert_recipient.sh`, `tests/test_err_trap_errtrace.sh` and `library/skills/gitguardian/test.sh` named paths such as `/state`, `/local` and `/log`, the last under `rm -rf`. `library/skills/gitguardian/test.sh` is the one packaged file here: the wheel carries `library/`. It is the skill's own test and runs only when someone runs it.

`tests/test_harness_scratch_dir.py` runs both instruments with a `mktemp` that fails as a full disk makes it fail, from a throwaway folder, and fails on the old code because that folder is gone. It runs the six other scripts the same way and expects each to stop with exit 3. Reproduced on a 600 MB disk image filled to the last block: before the fix the throwaway checkout on it was removed; after it, both instruments exit 3 and the checkout is intact.
