### Fixed — the setup guide can start again over a kept Preview (#3065)

On a real computer a person pressed Preview team, saw the prepared team with Launch, and closed the workspace before pressing Launch. Closing it ends the guide run, and the guide's listener is what serves the workspace before Launch. Everything on the computer was intact, but the guide refused to start again ("a first-team operation is retained"), so nothing could serve the workspace and Launch could never be pressed. `host_owner_setup.run` now lets the typed guide over the browser carrier go on over exactly one more state: the setup approval is active and holds no launch, and the update record is that approval's own Preview (`OwnerSetup.kept_preview`): accepted by `OwnerSetup.operation`, finalized at quiesce, no stage error, configuration not committed, never dispatched (nothing a local continue saves first: quiet or notice support, job support or a dispatch), and named by the Preview row kept for that approval, whether or not its 600-second window has passed. The guide then runs as it does for a returning person: no card is asked again, the approval is not renewed, and it sends its usual ready frame for the same approval; the workspace's setup read shows the kept Preview, or says it expired. If the approval lapses after that check, the guide refuses with the same message before any approval card. Every other state refuses exactly as before, including any reserved or dispatched Launch, a terminal guide run, the SSH-carried guide (its Preview and Launch never needed a run alive), and a run asked to finish a setup. No frame, key or sentence changed. After the window has passed a person still cannot make a new Preview; that is a separate decision.
