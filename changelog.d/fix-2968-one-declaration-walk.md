### Fixed — one walk for what a bot declares, and the daily check probes each per-org push token (#2968, #2969)

Two walks answered "which credentials does this bot declare", and since #2958 they disagreed. The daily credential check (`claudlobby host credentials check`) added the GitHub App's three `GITHUB_APP_*` variables for a bot with `github_app:` and refused a bot whose walk raised. The reconcile (`claudlobby host credentials reconcile`) and the doctor's credential check did neither: they read a bot routed through the App, without the App's MCP fragment, as declaring none of the App's variables, and they skipped a bot whose walk raised, reading it as declaring nothing. Now all three read one walk, `credentials.declared_by_bot`. For such a bot the reconcile counts the App's variables as declared, under `mcp/github-app`, where it reported a stored one as a value no bot declares and a missing one not at all. A bot whose declarations cannot be read now stops the reconcile with an `unavailable` error naming the bot, and the doctor's credential check warns, naming it, and probes nothing. The reconcile's count of equipped MCP servers counts only fragments a bot is equipped with. The walk also reads the variable a bot's `telegram.token_env` names, which the composer registers as well, unless it is the channel plugin's own `TELEGRAM_BOT_TOKEN`: the reconcile counts a stored Telegram token as declared, where it reported it as a value no bot declares, and the daily check keeps one Telegram row per channel bot, from its own check.

And the variable holding each org's push token in a bot's `git_credentials` was declared to none of them, so the daily check never probed it: a revoked, expired or missing push token showed up nowhere, and the first sign was a failed `git push`. The walk now declares each one under `git_credentials/<org>`. The daily check probes each token as it probes `GITHUB_PAT` (`GET /user`), under a row of its own, `git_credentials_<VAR>`: a token with no value at the host, root or fleet tier is a `fail` naming the orgs that declare it, a token two orgs share is probed once, and a variable the GitHub check already probed that tick is not probed again. A row for a token no bot names any more is removed, and a fleet that names none logs that none was checked. A direct run of `creds-check.sh`, which reads no declarations, checks no push token, as before. The reconcile counts a stored push token as declared, where it reported it as a value no bot declares.
