### Fixed — The install status check recognises its own installation once setup has started

Reading the status of a web-prepared installation used to answer "existing installation, inspect this computer" from the moment the setup guide created anything beside it (the Claude program, the private settings folder, the first state files). Anyone who closed the setup page after that point could not pick setup up again from the web: every new page stopped at "Existing or unsafe application state needs inspection".

The read-only status now reports `recorded_in_use` when the same completed preparation is still exactly verified (its record, pinned source, environment and entry points) and the only difference is the fixed state this product's own setup adds: the `host-policy`, `provider-bin` and `provider-profile` folders, and whatever setup and the running app keep under the data and staging folders. It reads none of that later state and takes no runtime lock. Any other name beside the installation, a later folder that is not a private folder of the same account, a missing record or a missing skeleton still refuses as before, and `prepare` still refuses anything but the untouched skeleton, so nothing is adopted or replaced.
