### Fixed — on Linux, setup now installs units where keepalive reads them, and activation refuses any other directory (#2610)

Both setup guides used to install units into the first directory `host setup` lists. That list is systemd's search path in its own order, and on Linux it starts with `~/.config/systemd/user.control`, which systemd keeps for configuration made through its D-Bus API. The units loaded there, but keepalive and the registration checks read only `~/.config/systemd/user`, so keepalive skipped every bot. The guides now select `$HOME/.config/systemd/user` (`$HOME/Library/LaunchAgents` on macOS) and stop unless `host setup` lists it. `host activate`, `fleet setup` and `host owner allow-setup` refuse any other directory and name the right one; activation refuses before it waits for its lock. When the search path leaves that directory out, the refusal names `XDG_CONFIG_HOME` and `SYSTEMD_UNIT_PATH`, which change that path. `bot move` installs the moved bot's unit in that directory too, and refuses before it stops the bot when activation would refuse. `host setup` without `--json` and the `--install-directory` help name the directory. A unit an earlier activation installed elsewhere stays where it is.
