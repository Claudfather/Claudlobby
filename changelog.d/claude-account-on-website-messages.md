### Added — a message sent from the website records the account that sent it (#NNNN)

A request receipt can now carry `provenance`, kept outside the request's intent. A message sent through the website's connected session records `{"carrier": "connected", "account": <the bound website account>, "binding_revision": <n>}`, taken from the same binding snapshot the action's scope was checked against. It records the session that sent the message, not proof that a person typed it. A direct owner session and a message sent on the computer record nothing, and the same request ID with and without it is the same request. One other shape, `{"carrier": "setup_finish"}`, is accepted and read but nothing writes it yet; anything else is refused. Receipts without the field decode and are written back byte for byte as before. `request show` returns the field, and prints a `provenance` line when it is present. A core that has this must keep reading the field: receipts written with it stay readable only by a core that knows it.
