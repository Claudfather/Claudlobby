### Docs — a handoff directory is refused when it cannot be searched, not when it cannot be read (#2935)

Two entries for #2927 say that `bot handoff` and a self restart refuse a directory above the session's own directory (`data/claudna` or its `sessions/`) that cannot be searched or read. As the code has it, read permission plays no part. The readers walk down to the session's own directory and look up each directory on the way with `lstat`, which needs search permission on the directory it looks in, not read permission. So `data/claudna` or its `sessions/` is refused when it cannot be searched, and a directory on the way is refused when its lookup meets an I/O error. One that can be searched but not read is not refused. Inside the session's own directory, an I/O error refuses nothing: the session reads as having no handoff of its own, as when that directory cannot be searched, and the readers read `.claude/session.md`. Nothing that runs changes. `HandoffDirectoryRefused`'s docstring now gives this account. New tests pin an I/O error in both places. They also pin `bot handoff`'s refusal of a `data/` that is not the user's own, which names that directory, and a usage refusal by a subcommand's own parser, which exits 2 when stderr cannot be written.
