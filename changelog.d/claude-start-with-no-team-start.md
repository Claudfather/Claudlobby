### Added — start a paired, linked computer with no team (#3054)

`claudlobby/plane/owner_start.py` adds `start(paths, store, terminal, *, consent=None, owner_plan=None, directory=None)`. It starts a fresh computer whose owner is paired and whose workspace is linked. One `START-WORKSPACE` approval covers it. Before anything is written, the approval lists the database, the native directory and whether the start creates it, each resident service and each scheduled job, read from this computer's host jobs with any planned settings change applied, the updater's own job unit, the installed programs, and that settings file's path and hash. An absent native directory is created only after approval. It refuses before the approval a native directory that is not in this computer's catalog or is not a real directory, an existing update record, retained state from today's guided setup, and planned settings for another workspace or another file; after the approval, under the update lock, it admits the computer again and refuses another running update or a settings file that changed while the approval waited. A failure after approval names the record's request id when a record exists, and otherwise says that nothing was started and whether the planned settings were saved. The settings commit, preparation and dispatch run under one update lock, so a second approved card refuses and dispatches nothing. A declined approval leaves no update record, database, configuration or settings change. An approved start commits the planned settings, then prepares and dispatches one first install that names no team files. It does not wait for that install. Called again, it returns the same request while the start runs (its lock held, or its job running), `started` once it is done (also when it finished while being read), and core's own unfinished-update line with the request id when the start stopped: a refused or vanished job, or a stage error. It never continues a record: that is `host update continue`. No terminal command calls `start` yet, and the guided first-team setup still refuses a computer it did not start. This follows the workspace-first setup flow approved on 2026-11-21.
