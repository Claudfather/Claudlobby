### Changed — the eval protocols compose as a short trigger, and their procedure lives in the `run-eval` skill (#717)

`eval-workflow` and `ab-gating-rollout` now say only when each applies: an eval is due when its result could change a decision, and a PR whose justification is a measurable effect needs a verdict, where INCONCLUSIVE never passes. The procedure they carried is in the `run-eval` skill, which a bot loads when it runs an eval: the pre-registration, sizing, the verdict and the report, version pins, the dry-run default and the real-run gate, and the honesty rules. The skill also says what each verdict does to a PR. Each protocol requires the skill, so a bot that composes either one has it. A bot that composes both carries 3,959 fewer tokens on every call (4,333 to 374, counted with Claude Code's own `/context`), from its first session after a host update.
