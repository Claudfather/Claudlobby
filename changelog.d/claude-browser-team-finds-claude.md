### Fixed — First team on a Linux computer set up from the website: the bots find Claude and start

Nobody had launched a first team on a Linux computer set up from the website yet; reading the code against a real one showed it would not start. Website setup installs one checked copy of Claude in the setup's own folder (`~/.local/share/claudlobby-browser/provider-bin/claude`) and puts no `claude` on that computer's path, but the bots still looked for `claude` on the path. Each bot would have stopped with "could not measure the configured Claude provider" before its window opened, and the launch would have waited out every bot and then refused to start the daily jobs. A computer set up this way now runs exactly that checked copy, for bots, version checks and scheduled jobs alike, and never another `claude` it might find on the path; if the checked copy is missing, the bot fails saying so. Computers set up from a terminal choose Claude exactly as before.

Two more stops were behind that one. Claude's first-run screens (a colour theme, then a notice) would have waited for a key in each bot's window, because the Claude profile kept for the bots had only ever been used to sign in. On a computer set up from the website, a bot starting on that profile now marks its first-run onboarding done for the version it runs; everything else in the profile is left as it was. Neither screen asks for consent. Computers set up from a terminal are not touched, so a profile nobody has signed in to yet still gets Claude's own first-run screens, sign-in included. And the daily Claude update would have tried `npm install`, which that computer does not have and which could not update the checked copy anyway, then raised a failure alert every day. When the bots run the checked copy, the update job now writes one line in its log saying the setup owns that version and does nothing else.

This change is for Linux. A Mac set up from the website still stops before the first bot's window opens: before each start, the bots' Claude has its version checked under a time limit, and a Mac without `timeout` or `gtimeout` can set that limit only with the setup's own Python. The check is not yet given that Python (`CLAUDLOBBY_NATIVE_PYTHON`, in `claudlobby/claude_version.py`), so it refuses and the bot does not start. That needs its own change.
