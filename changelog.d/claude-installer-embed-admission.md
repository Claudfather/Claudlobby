### Changed — the installer and the owner guide embed only the Mac admission code they call

`host-install-v1.sh` and `owner-guide-v1.sh` each carried a byte-exact copy of all of `darwin_runtime.py`, but call only `admit_profile` and `environment` on it. `darwin_runtime.py` now lists everything those two reach first (the constants, the descriptor, the profile type and the read-only checks) and ends that part with a `# END DARWIN RUNTIME ADMISSION` line; the download, extract, prepare, discard and `main` code follows it. The two scripts embed only the part up to that line, so `host-install-v1.sh` goes from 117459 to 91675 bytes and `owner-guide-v1.sh` from 65249 to 39465, and the installer's command as sent to a computer has that much more room under the one-argument limit. `darwin-runtime-v1.sh` and `installation.py` still embed the whole module. Definitions were only moved: no function body changed, and a test runs the admitted part alone, checks it defines every name the scripts read on it, and refuses any other use of the embedded module that the check could not follow. These scripts' bytes change (as do `darwin-runtime-v1.sh` and `installation.py`, because the module's order changed), so the website must move its pins (operations lock) for them.
