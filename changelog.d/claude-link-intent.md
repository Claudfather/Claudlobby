### Added — the computer run's link intent: one card that allows Claude sign-ins on a started computer (#3119)

With `link_claude: true` on the guide's first line and on the start (only `true`, only the computer run), a started Linux computer's run asks Claude's install when it is missing, then one card (`link_provider`) whose yes writes a link approval and answers `link_ready` with its generation. Every refusal is decided before any card, in order: the guide's own `revision_differs`, the run's admission (`installation_changed`, `use_full_guide`), then `not_here`, `not_started`, `already_linked`, `signin_live` or `signin_unconfirmed` (the sign-in lease, probed from the run's own process), `busy`, `credential_present` and `environment_format`. A no or no answer changes nothing (`declined`, `expired`); after the run installed Claude it is `installed_declined` or `installed_expired`, so the page can say Claude is installed but not linked. A lease held over an ended attempt other than a quiet child's is now probed again, up to 50 times 0.01 seconds apart, before it refuses, in the writer, at begin and in the run, because a worker in another process closes its lease just after its last row. Without the key the run is exactly today's and asks no Claude card. Nothing sends the key yet: it is inert until the website sends the intent and moves its core pin.
