# claudlobby/ — placement guidance

The Python compositor. This file is the boundary at the seam and, below it, the module map
(moved from the root `CLAUDE.md`, which keeps only where to start).

**What belongs here.** Composition and policy code: `fleet.yaml` parsing (owned here — parsed
nowhere else in the stack, by design), generation, validation, permission grants (#644),
status/observability, path resolution, migrations, scaffolding.

**What must never land here.**

- **Knowledge mechanics.** `paths.py` is the only module that may import `claudron.*` (the
  optional `[vault]` extra, composition-time fleet-overlay resolution only). No module reads or
  writes vault note content — bots reach knowledge through the CLI door at runtime.
- **Assertions about sibling surfaces not shipped at the pinned floor.** `claudron_compat.py` is
  the floor SSOT; the validator checks the door that exists (the CLI), never a hypothetical one
  (the parked MCP fragment stays unbuilt per decision C).
- **Skill or agent behavior** — prompts and procedures are composed *from* `library/`, never
  hardcoded in compositor logic.

**Placement test** (one line): does it transform `fleet.yaml` into a running bot, or police what
a bot may do? → here. Behavior → clauDNA / `library/`; knowledge → Claudron. Full algorithm:
Claudron repo, `documentation/plans/2026-07-20-claudfather-boundary-separation.md` §10.3.

  credentials.py      — Credential reconciliation (#1104): declared vs stored vs equipped-bot. Answers **shape 1** (declared, no value) and **shape 2** (value, no equipped consumer), and **deliberately refuses shape 3** (a declaration and its consumer naming DIFFERENT keys), which is what actually bit the estate — a valid Railway token in a fleet `.env` nothing read, a dead one ambient that `creds-check` read, and the real consumer reading `~/.railway/config.json`. Shape 3 is a property of a PAIR spanning the claudlobby/plugin boundary, and `CLAUDE.md`'s own rule governs it: *consume siblings by contract, never by assertion*. Grepping the plugin tree to learn what it reads is assertion — correct today, silently wrong the next time the plugin moves its read path, with **no signal at the moment it turns wrong**. So shape 3 emits `UNKNOWN — no consumer contract published for <integration>` as a **printed and counted first-class result**, and the summary always carries an `unknown=` count plus "This is a gap, not a pass": a validator that silently omitted it would be indistinguishable from one that checked and found nothing, recreating the bug inside its own remedy. The seam it resolves through is `consumer_contract:` frontmatter, named here so the consumer-end half of #1104 has a target rather than an invention. **Declarations come from `mcp_resolve.required_vars`, never a private scan** — the first version regex-scraped `${VAR}` and reported `TOKEN` unsatisfied on the live estate, when the contract scopes it per instance to `NOTION_TOKEN`, which was present all along: a hand-rolled reader manufacturing a false FAIL inside the tool built to end false FAILs. Tier resolution likewise goes through `Paths.env_file` (fleet `.env` if present, else root — one or the other, **never merged**), so a value stored only at root while a fleet reads its own `.env` reports as **"shadowed, not missing"** rather than absent; the two have different remedies and collapsing them sends someone to add a credential that already exists. Present-but-empty is likewise distinct from absent. `UNKNOWN` alone never exits nonzero — a disclosed gap is not a defect, and failing on it would train operators to suppress the check and lose shapes 1 and 2 with it. **No credential value is ever emitted**, only key/presence/tier. Backs `claudlobby creds-reconcile`; wrapped by `tests/test_credentials.py`

The registry scan records `claude_version: null` with `claude_version_unmeasured` beside it, and the host contract refuses anything but X.Y.Z or that pair
  switches.py         — THE SWITCH REGISTRY (chunk N): every knob the shipped system has, declared once. **The rule: a job or door is ON by default unless it deletes data, spends money, mutates operator source, or sends outbound to people at scale**; whatever stays opt-in is NAMED where the operator looks, with the one line that arms it. The reason is not caution about defaults — it is that a behavior nobody can see is a behavior nobody has: a dozen doors shipped dormant, each for a defensible local reason, and the composite was a system whose advertised workflow ran nowhere unless someone had read a dozen source comments. Four switches stay off and each states which category keeps it there (`update-siblings` mutates source, `session-digest` spends, `code-audit-sweep` spends + posts, `weekly-worker-restart` bounces live sessions — the stated fifth category, since durable context is what this system exists to keep). Polarity is a FIELD, not a convention (`opt-out` / `opt-in` / `silencer`), and only an exact `0`/`1` decides — an empty assignment wins at its tier (#1213) and is not a `0`, which the shell gates, the composer and this module all read the same way. Every consumer DERIVES: `composer.FLEET_JOB_ARMING`/`HOST_JOB_ARMING` (which unit carries which `Environment=` line — and post-flip it is the **`0`** that must reach a closed scheduler env, #1383 inverted), the validator's dead-flag warning (a `*_ENABLED` key in one of OUR namespaces that no switch claims is DEAD — the namespaces are derived too, so a fleet's own `MYTOOL_ENABLED` stays quiet and a door deleted tomorrow warns without a new list), and the three rendered surfaces (`claudlobby doctor` / `doctor --switches`, `plane doctor`'s plane subset, and the closing table of `lib/setup-fleet` + `lib/setup-system`, which call the ONE renderer rather than copying it into bash). `status`'s header names any REACTION door that is off, scoped to the three that change whether anything happens at all — a header listing every knob would be scrolled past, which is the same failure as saying nothing
  source_state.py     — The unreachable-vs-empty rule, decided once (#1216/#1014). **A reader that cannot reach its source must not return the same thing as a reader that found nothing** — those two answers have opposite remedies ("wire the instrument" vs "there is genuinely no work") and collapsing them fails toward *everything is fine*, the direction nobody audits. The line is **presence, not emptiness**: a ledger that exists holding zero rows is legitimate and "nothing matched" is TRUE for it; only absence or an IO failure makes that answer a fabrication. Extracted because the rule was already implemented twice, differently, and missing three times — `brief.py` probed and OMITTED with a `degraded[]` entry (right for a composite door whose other sections stay sound), `events`/`uptime` printed and returned 1 on an unreachable bots dir (right for a single-source command), while `report-back`, `workstreams` and `dispatch-overdue --orphans` returned a clean empty answer at rc 0. Three expressions of one rule is how the fourth reader gets it wrong. What is shared is the **classification and the wording**, never the parse — the sources are JSONL, JSON and text logs, so each caller parses its own format and picks its own remedy. `probe_source` tests **openability, not `is_file()`** (a file that stats fine and then raises is the mode that takes out a read door, and a stat-only probe certifies it), and classifies a directory-where-a-file-belongs as ABSENT rather than unreadable, because `IsADirectoryError` is an `OSError` and the naive ordering sends someone to run `chmod` on a path that is simply not a file. **Where the disclosure goes is the caller's, and it varies by consumer — measured, not stylistic**: `dispatch-overdue.py`'s stdout is PARSED (`fleet-pulse.sh:142` reads it into an orphan cache; `report-back.sh:117` pipes `--open` through `awk '{print $3}'`) so a line printed there becomes a phantom row and the refusal rides stderr + rc, while `claudlobby report-back`'s stdout is a human table nothing parses and a stderr-only disclosure is exactly what hid #1216 for a day. `--json` flips a command's stdout to machine-facing, so the disclosure moves to stderr there too. **rc always carries the refusal; the text goes wherever stdout is not machine-parsed** — rc alone is invisible to a human at a terminal, a stdout line alone is invisible to a script. It never raises: a read door that crashed would trade a false all-clear for an outage. `brief.py` aliases these literals rather than redefining them, since they are emitted verbatim in its schema-1 envelope. Wrapped by `tests/test_source_state.py`
  claudron_compat.py  — Claudron compatibility floor — min capability per integration surface
