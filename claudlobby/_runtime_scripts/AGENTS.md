# claudlobby/_runtime_scripts/ — placement guidance, authoring rules, script reference

Bash lifecycle scripts: start, supervise, dispatch, report, maintain. This file is the boundary
at the seam, the authoring rules, and every runtime script's full reference. The root `CLAUDE.md`
keeps a one-line index of the scripts, for routing; the detail lives here.

**What belongs here.** Host- and fleet-lifecycle mechanics: supervision, timers, dispatch,
reporting, health checks, migrations, setup.

**What must never land here.**

- **Direct vault access.** Knowledge is consumed through the `claudron` CLI door only, in the
  title and path pointers only, never note bodies — the worker reads files
  itself. Resolution comes from the contract env (`CLAUDRON_VAULT_PATH`); no script opens files
  under a vault's note tiers (the set Claudron owns in `VAULT-STRUCTURE.md §Directory contract` —
  point at it, don't re-list it here).
- **Agent-facing behavior.** A procedure a *bot session* should follow is a skill (engineering →
  clauDNA; fleet command → `library/skills/`), not a bash script that prompts it.
- **Assertions about unshipped sibling surfaces.** Scripts guard on what the pinned floor ships
  (`claudron_compat.py`), and degrade fail-open when a sibling is absent.

**Placement test** (one line): operates the *host or fleet* → here; steers an *agent session* →
a skill; touches *knowledge* → through the door. Full algorithm: Claudron repo,
`documentation/plans/2026-07-20-claudfather-boundary-separation.md` §10.3.

## Authoring rules

1. Source `lib-common.sh` for shared helpers (OS detection, bot.conf loading, safe mktemp)
2. Always use `set -euo pipefail` — use `|| true` for intentional failures
3. Quote all variables. Use `printf '%s'` instead of `echo` for values that may contain tokens
4. Test on both Linux and macOS where applicable (use `lib-common.sh` OS detection helpers)
5. Never hardcode fleet names, user home dirs, or Homebrew paths — use env vars and detection
6. No apostrophes in comments inside `$( )` — bash 3.2 (macOS `/bin/bash`, the shebang target) does not strip comments while scanning a command substitution, so a stray apostrophe corrupts quoting for the rest of the file (gate: `tests/test_bash_parse.py`, which covers `claudlobby/_runtime_scripts/` and every `library/**/*.sh`)

## Script reference

replaced older scripts; a row that says "this file" meant that file. The root index says what

| `start-bot.sh` | Launches a bot's tmux session with env vars from bot.conf. Also arms `session_cli_path` (#1567): on a venv-only install it symlinks just the `claudlobby` name — never the rest of `.venv/bin`, which would shadow a bare `pip install` inside the session — into a host-local `state/bin` and appends that dir to PATH, since nothing a session already resolves may change. The readiness poll's ceiling is wall-clock, not a probe count, and its TIMEOUT line names the last `bridge_state` seen (`wait_bridge_ready_state`, #1573); plugin updates run at most once per (boot epoch, plugin) rather than every start when `BOOT_PLUGIN_UPDATE_ONCE=1` (`plugin_ensure`) |

| `spin-down-bot.sh` | Inverse of spin-up: guaranteed teardown/reaper for canary/throwaway bots — removes supervision, kills the tmux server, drops the bot's fleet-state key; `--purge` also removes the bot dir. Emits a `bot_teardown_started` receipt (action/actor/fleet/bot_dir/expected_return/reason) to the **fleet** ledger so it outlives `--purge`, written *before* the legs run so a crash mid-teardown still leaves a record. **On by default since chunk N** — the receipt is the one record that outlives a `--purge`, which is exactly when a reader has nothing else to go on; a fleet turns it off with `SPINDOWN_RECEIPT_ENABLED=0` in `fleet.yaml` `bots.<bot>.env:` (bot.conf is the carrier that reaches a door running in a bot's session — a `.env` tier does not) and the door says so out loud, so a missing receipt is never a mystery. Also the lever for RAM pressure — check for uncommitted WIP first: `systemctl --user stop` does not hold (the 60s keepalive walks a stopped bot back up within a minute), and de-enrolment is the one thing keepalive cannot undo; reconcile surfaces the result as `unsupervised-down` (#828) |
| `cli-context.sh` | Private import-free context checks for native adapters: require an explicit absolute host data root and the composed absolute CLI executable where a door needs them. | `env-tiers.sh` | The `.env` tier cascade as a standalone query door (#1214/#1226). Prints the four tiers in runtime sourcing order — `host` (`~/.env`), `root`, `fleet`, `bot` — one `<tier>\t<path>\t<present|absent|unresolved>` row each. **It holds no logic**: the order lives once in `env_tier_rows` (lib-common.sh), which `start-bot.sh` itself sources, and this file exists so a non-bash consumer — the Python compositor, via `claudlobby/env_tiers.py` — can ask the runtime its own question instead of keeping a second copy of the answer. The compositor **refuses** rather than falling back when it cannot reach this door: a fallback ordering IS the second copy, and it would be consulted exactly when the two have diverged. Precedence is shell assignment semantics and nothing cleverer — the most specific tier that ASSIGNS a key decides its value, **including assigning it empty**, measured in both bash and zsh. That is not a corner case: it is why `GITHUB_PAT` was present-but-empty at the fleet tier on half the estate and the GitHub MCP had been wired to `""` there invisibly (#1213). A cascade that treated empty as absent would report those fleets healthy, which is the defect rather than the fix. All four rows are always emitted — a consumer that must say "host: nothing there" cannot otherwise tell a tier that held nothing from a tier the function forgot — and `unresolved` is a third state again: the tier does not APPLY (no fleet name, no `CLAUDLOBBY_ROOT`), which is a different fact from a tier that applies and is empty |

| `claude-session-pid.sh` | Answers "which Claude Code session am I running INSIDE?" as a standalone query door (#1525) — a parent-child walk UP the caller's own ancestry, never a process-table search. The four status skills it serves (`selfcheck`, `status-personal`, `review-status`, `eng-status`) identified themselves with `pgrep -f 'claude' | head -1`, which on a shared-uid host matches every bot on the box. **The failure was not a lottery with one winner**: a tmux server always forks the Claude process it hosts, so its pid is always lower (12/12 across three fleets, zero counterexamples), which makes the earliest-starting match structurally a tmux **server** — so `head -1` could not return a Claude session for ANY caller, including the bot whose own server won the race and got its 4 MB supervisor instead of its 584 MB session. It never errored, and "2 days" is a plausible uptime; every caller got the SAME wrong pid, so two bots comparing notes read identical numbers as corroboration. These skills run inside the session they describe, so a bot never needs to search for itself. **Refuses loudly** — prints `unknown`, exits 3 — and never falls back to a scan: a fallback would be a second copy of the predicate, consulted exactly when the two have diverged (`env-tiers.sh` refusal, same reasoning), and a plausible wrong number is the whole defect. | `lib-common.sh` | Shared helpers: OS detection, bot.conf loading, safe mktemp, and `pane_send_verified` — the ONE send-keys/settle/Enter/verify-retry primitive every keystroke injector routes through (#763). **The payload crosses the pty in CHUNKS, never one write** (#1493): `PANE_SEND_CHUNK_BYTES` bytes at a time (default 400: under the receiving TUI's 800-byte paste threshold, #1876, and so under the 1024-byte macOS pty queue too), `PANE_SEND_CHUNK_SETTLE_S` apart (default 0.15s) so the reader drains, each via `send-keys -l --`, then one Enter after the last. Measured: a single write lost the HEAD of 85 of 180 large sends in a week — the macOS input queue holds 1024 bytes and, with `IMAXBEL` cleared by `cfmakeraw`, FLUSHES on overflow instead of dropping the incoming byte, so a reader that has not drained the first 1 KB loses it, envelope and task id included, while the send still records `pane_submitted`. `-l` matters on its own (without it tmux resolves the argument as a KEY NAME first); the split is byte-safe for UTF-8 under `local LC_ALL=C` with a bounded back-off off continuation bytes; the wait for the payload to show, the verify and the pre-draw repair all stay anchored to the WHOLE payload, and the repair resends chunked. `PANE_SEND_CHUNK_BYTES=0` restores the legacy single send and exists ONLY for `send-size-probe.sh`'s control arm. Its verify anchors to the last prompt-glyph line, never a fixed `tail -N`: Claude Code draws border, hint and mode footer *below* the input line, so a fixed depth either never reaches the prompt (the retry silently dies) or reaches up into the transcript (a submitted command is still visible there, so Enter re-fires at an idle prompt). It also waits for the input box to exist before sending at all (`pane_await_input_box`, #860): a send issued before the TUI draws is lost outright, and before #1236 the glyph-anchored verify read that loss as a *clean send*, because a glyph-less pane holds nothing unsubmitted. Bridge readiness is not a proxy for the box (poller up at 3-9s, box drawn at 10-19s). A glyph-less pane means either mid-turn or never-drawn, those need opposite responses, and a capture of the alternate screen buffer can only ever describe the present, so a signal from before the Enter carries the memory: the verdict latched before the keystrokes went out, which only the unambiguous `never-drawn` case acts on (a longer wait, and a repair that resends the whole payload, not a bare Enter), and since #1236 the sighting of the payload in the box, which is what lets a later empty or glyph-less frame count as a submit. **The Enter waits for the payload to show** (#1236): after the keystrokes the send polls until the input box shows the END of the payload (`pane_shows_payload_end`; `PANE_SEND_SHOWN_TICKS`, default 10 s, the never-drawn repair running inside that wait) and only then presses Enter, so a submit counts only as seen, then gone. Never shown, it withholds the Enter and returns 3 (`send_unsubmitted`, `payload-not-shown`): a blind Enter read together with unread text is kept in the box as a CR and holds the prompt, which is how boot prompts were held while the verify reported them clean. A box still showing the payload a verify window after the Enter gets another, up to `PANE_SEND_ENTER_TRIES` (default 4) in all, each a `send_retry`; still there after the last, the send returns 3 (`send_unsubmitted`, `payload-still-in-box`), never 0. A paste-framed payload counts as shown by its `[Pasted text` placeholder, and a message queued behind a running turn counts as gone (the box shows only "Press up to edit queued messages"). Measured on claude 2.1.285: an extra Enter on an empty box does nothing, mid-turn or idle, queue or not, and Enters piled up behind a stopped TUI submit once. Callers under `set -e` handle 3 (start-bot through `boot_send_settled`, keepalive by leaving the reload pending). Derivation, the rejected discriminators, and the stated bounds live beside the verdict constants in the source. Also `install_error_trap`, which arms `set -E` on behalf of every caller (#844) — a bare ERR trap is not inherited by shell functions, and `claudlobby/_runtime_scripts/` does nearly all its work in functions, so without errtrace the fleet's error breadcrumb only ever saw top-level failures. A script that hand-rolls its own `trap … ERR` rather than calling the helper is not covered. Also `declared_bots_strict` and `boot_start_class` (#1043) — the first is the LOUD roster door that must never be swapped for `parse_fleet_bots`. **The discriminator is what the caller does with an EMPTY result, not whether it is an "action" or a "measurement"** (#1146): a soft-fail is right wherever empty means *do nothing*, and wrong wherever empty **licenses a write or a delete**, because there absence of evidence is being read as evidence of absence. The old action/measurement framing endorsed a live destructive defect — a prune is an action, so the rule blessed it, and a CRLF-drifted sibling manifest let one fleet delete another fleet's live state row at rc 0 (#1143). Note also that `bot_in_fleet` **inverts** an empty roster into "every directory is declared", so six callers reach their work through a predicate that turns *do nothing* into *do it to every bot on the host*; the second types how a session came to life and **denylists the invariant rather than allowlisting the variant** — startup payloads are authored per bot and vary without limit, while the channel injection and the `tool_result` record have exactly one shape each, so those are matched and a payload is whatever is left. `plane_emit_events` never blocks a door but SURFACES its result in `PLANE_EMIT_LAST_RC` (feed it a here-string, never a pipeline, where the result matters) — F18 R1: there is no legacy append left to fall back on, so a door says an unrecorded action LOUDLY instead; `plane_write_retired`, `plane_retirement_covers`, `plane_door_key`, `plane_fleet_tier_value`, `plane_emit_detached` and `rotate_jsonl_by_ts` are gone with the four-fact machinery. `emit_fleet_event` (Phase B → F18 R1) lands every fleet event on the plane and NOWHERE else — the fleet from `FLEET_NAME` or the timer units' `CLAUDLOBBY_FLEET` (a door with neither discloses and records nothing) — a system event anchored on the bot's actor (or the fleet, for a fleet-level receipt) by ALIAS, stamped UTC, its source_ref `fleet-events:sha:<content key of the row as the retired ledgers wrote it>` (the provenance every reader selects on), its detail `{source, legacy_ts, data}` so the plane re-renders the legacy row byte for byte. The emission is WAITED on, bounded (`plane_emit_bounded`, `FLEET_EVENT_EMIT_TIMEOUT_S` default 10s): this door runs inside every `claudlobby/_runtime_scripts/` hot path (the keepalive tick's ERR trap included) and a wedged rung must never hold a tick for a minute; a failed or reaped emission is disclosed as not recorded — the shim's spool is the durability below that. It RESTORES the caller's `PLANE_EMIT_LAST_RC` afterwards (the structural lens reproduced a report door whose failed emission read as recorded because a nested `send_miss` had succeeded — a report recorded NOWHERE). `resolve_alert_target` returns the alert chat AND its sender (the channel state dir) as ONE pair from ONE source, or REFUSES with a reason that names what to set (#1771): the escalation chat pairs only with `FLEET_PULSE_ESCALATION_STATE_DIR`, an env chat with the `TELEGRAM_STATE_DIR` beside it or a bot of the caller's own fleet whose own chat it is, and no env chat takes both halves from one bot — a chat from the env with a token from whichever bot a scan found first is how one fleet's alerts went to a group its bot was not in; `channel_state_token` is the one reader of a channel dir's token (tg-post and creds-check). `switch_is_on VAR "<door>"` is THE opt-out gate every self-gating door calls (chunk-N fold) — polarity in one place, unset or anything but an exact `0` is on, a `0` prints the door's OFF line and returns 1 (the shell twin of `env_tiers.resolves_to`, so an empty assignment is a win at its tier and is NOT a `0`); `walk_back_uncomposed_host_units` disables and removes every INSTALLED `claudlobby-*` host unit the current compose no longer emits — dormancy that only applied forward left `update-siblings` (which mutates operator source) enabled on every host that had run the installer — and REFUSES on an empty compose, because a torn generate is an unreachable instrument rather than a host where everything is dormant. `fleet_claude_bin` is THE answer to which claude the fleet launches (#1768) — `CLAUDE_BIN` when set, else the staged link `$CLAUDLOBBY_ROOT/state/bin/claude` when it resolves to an executable, else the bare name on PATH as before — and every fleet consumer (start-bot, plugin_ensure through it, reload-fleet, transcript-digest, the update job's own version check) goes through it, which `tests/test_fleet_claude_bin.py` ratchets; `atomic_link_swap` moves a symlink in one rename(2) (`os.replace`: BSD mv has no `-T`, `ln -sfn` is atomic only where the platform's ln makes it so, and both it and a plain `mv` put the link inside a directory sitting at the link path and exit 0). `fleet_launch_path` is THE PATH a bot session launches under: start-bot.sh exports it, and the update job resolves the fleet's claude under it rather than under a hand copy of the order (#1772). `fleet_claude_path` is the FILE `fleet_claude_bin`'s answer resolves to (a bare name looked up on the launch PATH with `type -P`), for measuring the fleet's binary where `fleet_claude_bin` is for launching it. `measure_claude_version` is the ONE reader of a Claude Code version: the binary ran and the first line of its stdout carries X.Y.Z, or it is could-not-measure with a reason, never a sentinel. The update job, `claude-version.sh`, the eval harness's pin, the onboarding seed (which refuses at rc 3 rather than seed a stand-in), the send-size probe and the permissions ladder all go through it, and `tests/test_claude_version.py` ratchets every other `--version` read out of `claudlobby/_runtime_scripts/` and `claudlobby/`. `plane_armed` arms unless `PLANE_EMIT_DISABLED=1`; `PLANE_EMIT_ENABLED` is read by exactly one consumer, the generate-time registry scan (`registry_emit.py`, an opt-OUT since chunk N — only an exact `0` suppresses it), and by no door or hook — measured on the data flip: the pre-stop hook of every restarted bot ran with no flag in its environment and wrote its `handoff_skipped` into a legacy file the retirement had frozen, and an env-gated arming loses records the day the file is gone `pane_is_held` (#2070) is the held-box predicate keepalive asks before `pane_is_idle`: positive evidence of text on `pane_input_region`'s input line, never Claude Code's own suggestion (`Try "…"`), queued-message hint or a menu (a numbered option, or an offered "Esc to cancel"), and byte-safe under any locale, where the idle bracket matches a box border's bytes under `LC_ALL=C` |
